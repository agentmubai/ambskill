# ambskill

> agent沐白在用的 Agent 技能集合。当前收录两套：`amb-beiming` 把一位作者的成批真实语料，炼成一套能替人做具体任务的技能工具箱；`amb-paoding` 把对方的作品（朋友圈、短视频转写、直播、公众号）拆成写作技能——他怎么看事、每段要达成什么、怎么说。两套技能里引用的每句原话都由脚本逐字核过，改写过的引文进不了下一步；每条判断都能回到出处。

**支持：Claude Code、Codex、Cursor、ZCode、Grok CLI、WorkBuddy，以及其他能读 `SKILL.md` 的 Agent。**

ambskill 由 [agent沐白](https://github.com/agentmubai) 创建，收录他自己在用的 Agent 技能。

## ambskill 解决什么问题

ambskill 是一个技能集合仓。当前收录两套：`amb-beiming` 与 `amb-paoding`，每套各占 `skills/` 下一个目录，互不依赖，装哪套用哪套；`npx … -g --all` 与 `claude plugin marketplace add` 不变，Claude Code 插件市场里按插件名各装各的。

两套的分界一句话：**北冥（amb-beiming）炼的是这个人怎么判断，庖丁（amb-paoding）拆的是这个人怎么写。** 手里是自己的课程、访谈，想做一个替自己做事的分身，用北冥；手里是别人（或自己）的一批作品——朋友圈、短视频转写、直播实录、公众号——想让 Agent 按那个路数替你写一条，用庖丁。

下面这些处境，`amb-beiming` 直接对应：

| 真实处境 | 你会得到 |
| --- | --- |
| 讲过几十小时的课、录过一堆访谈，方法都在里面，但没人调得动 | 一套按任务切分的技能工具箱：一个路由器认领需求，若干任务技能出活 |
| 让通用模型「学你的风格」，它答得像你，细节却是编的 | 每条判断挂着原子 id，能回到你原话的出处文件与逐字原文；改写过的引文进不了下一步 |
| 想把内容做成 skill，可几百万字一个人读不完 | 一份预检报告先说清值不值得做、要切几批、工作量多大；几百万字由子代理并发读完，你只拍三次板 |
| 新一批课录完了，不想把整套重做一遍 | 只更新受影响的知识包，回归测试不掉档才算更新成功 |
| 手上有别人写的 skill，判断从哪来说不清 | 有原始语料就重炼成可溯源形态；没有就只做结构改造，并如实告诉你上限在哪 |
| 不知道做出来的东西到底比直接问模型强多少 | 两个模型评委盲评、三套题集、逐任务 PASS / WEAK / FAIL 的验收报告 |

下面这些处境，`amb-paoding` 直接对应：

| 真实处境 | 你会得到 |
| --- | --- |
| 收了对标账号两百条口播、三十天朋友圈，想让 Agent 按那个路数替我写，而不是「学学风格」 | 按结构聚成几种类型，每类一份写法书、一个技能，加一个路由器；你给事实，它出一条成稿 |
| 模仿出来形似神不似——句子像，站的位置不像 | 写法书第一章是「魂」：他怎么看事、替谁说话、结尾留什么，每条至少两篇原文作证；技能动笔前先过这一章 |
| 怕模型把范文里的人名、数字、行业搬进我的稿 | 事实不搬是硬规矩：范文事实一个都不许进你的稿，缺的标〔待补〕；交稿前有脚本核数字来源 |
| 拿到手不知道这类写法凭什么成立、我够不够格写 | 每段带「凭什么」：你的身份、你真懂的领域、你站哪一边——答不上来，技能如实说这一类你写出来会像壳 |
| 只有一篇写得特别好的，也想做成技能 | 单篇可标范文型单独成技能，检查按范文型放宽，说明里写清只基于一篇 |
| 后来又来一批料，形态跟原来不一样 | 增量分三档：同形态直接补；新形态料够就在同一箱子里另出技能；料不够只存原件，提醒你 |

## 快速开始

### amb-beiming：语料 → 任务技能工具箱

安装完成后，准备一个语料目录（子目录 = 一组材料，放 `.txt` / `.md` / `.srt` / `.vtt` 文本文件），在 Agent 里直接说：

```text
用 amb-beiming 把 ~/我的课程转写 做成技能工具箱，工程放 我的课程-workspace/
```

它会先盘点语料、打印规模与批次，再把预检结论交给你拍板。整个过程你只出场三次：**看预检结论、看加工样品、确认能力方案**。（后面补新料时，若新旧主张相反而作者自己没说过取舍，冲突表上那几行会再找你一次。）

另外两种用法——给已交付的工具箱补新料、把别人的 skill 改造成可溯源形态——说法与产出见下面的[能力一览](#能力一览)。

语料少于约 50 个文件、且总量不到 8 万字时，它会在预检报告里直说：读完手写一个技能更便宜。想自己一步步跑脚本，见 [amb-beiming 的完整说明](skills/amb-beiming/README.md)。

### amb-paoding：作品 → 写作技能

准备一个作品目录（子目录 = 一组，最好一组一个形态或一个来源人；短视频、直播先转写成文本），在 Agent 里说：

```text
用 amb-paoding 把 ~/对标口播转写 拆成写作技能，工程放 对标-paoding/。这是 <谁> 的短视频。
```

它会先盘点每种形态多少篇、够不够出技能，然后聚类型。你只出场一次：**看聚出来的类型卡，定名字与取舍**。之后写法书、技能、路由器、对裸模型的轻验收都由它跑完，交付一个自包含的成品箱。

拆什么形态出什么形态：一批朋友圈出写朋友圈的技能，一批短视频转写出写口播的技能。料里有大批长课程时它会先问你要什么——想模仿讲课腔调继续用庖丁，想替自己判断该换北冥。想自己一步步跑脚本，见 [amb-paoding 的完整说明](skills/amb-paoding/README.md)。

## 能力一览

| 工作目标 | 主要入口 | 常见产出 |
| --- | --- | --- |
| 把一位作者的成批语料炼成技能工具箱 | `amb-beiming`：「把这批语料做成技能工具箱」 | 路由器 + N 个任务技能、原子库 / 单元库、预检报告、验收报告 |
| 给已经交付的工具箱补新料 | `amb-beiming`：「给这个工具箱补这批新料」 | 只改受影响的知识包、新旧主张冲突表、回归结果 |
| 把别人的现成 skill 改造成可溯源形态 | `amb-beiming`：「把这个 skill 改造成可溯源形态」 | 有语料则重炼；无语料则结构改造 + 明确的上限说明 |
| 把一批作品拆成按路数替你写的技能 | `amb-paoding`：「把这批朋友圈 / 短视频拆成写作技能」 | 路由器 + 每类型一个技能（写法书 + 范文原文 + 事实核对脚本）、原件库、轻验收差距报告 |
| 给已交付的写作技能箱补新作品 | `amb-paoding`：「给这个箱子补这批新料」 | 同形态补进类型重写写法书；新形态另出技能或只存原件，附三档判定 |

炼出来的工具箱是自包含的：把成品目录 `product/<工具箱名>/skills/` 下的技能目录拷到任何宿主的技能目录就能用，不依赖本仓库，也不会自动装进任何地方。两套技能的成品前缀不同，装进同一个宿主目录不会撞名。

## 安装

### 通用方式（Codex / Claude Code / Cursor / ZCode / Grok 等）

```bash
npx -y skills add agentmubai/ambskill -g --all
```

只装其中一套：

```bash
npx -y skills add agentmubai/ambskill --skill amb-beiming
```

```bash
npx -y skills add agentmubai/ambskill --skill amb-paoding
```

WorkBuddy 用户把技能目录放到 `~/.workbuddy/skills/` 即可。两套都只要 Python 3.9+ 标准库。装好后新开会话，说「用 amb-beiming 把这批语料做成技能工具箱」或「用 amb-paoding 把这批作品拆成写作技能」。

### Claude Code 插件市场

```bash
claude plugin marketplace add agentmubai/ambskill
claude plugin install amb-beiming@ambskill
claude plugin install amb-paoding@ambskill
```

## ambskill 怎样工作

ambskill 本身不做调度：每套技能自包含，装哪套就用哪套，技能之间不互相依赖。下面先说 `amb-beiming` 的机制，再说 `amb-paoding`。

### amb-beiming

`amb-beiming` 把「语料变技能」拆成九段，每段有明确的完成门槛——产物文件在、校验脚本记录通过、输入哈希没变，三者缺一都不算完成。子代理的口头汇报不算数。

```text
一批真实语料
   ↓  S1 盘点   →  预检报告        ← 你看结论：可开工 / 收缩范围 / 补料
   ↓  S2 试点   →  加工样品        ← 你看样品；规则连续两批不改才冻结
   ↓  S3 萃取   →  原子库 / 单元库 + 折损审计
   ↓  S4 方案   →  能力方案        ← 你确认要哪些任务
   ↓  S5 蒸馏   →  每任务的方法论、案例卡、六层
   ↓  S6 成技   →  任务技能 + 路由器，体检
   ↓  S7 验收   →  对裸模型盲评，逐任务 PASS / WEAK / FAIL
   ↓  S8 交付   →  自包含成品目录
        ↺  S9 增量：新料只改受影响的部分，回归不掉档才算更新成功
```

三条底层规则决定了它和「喂给模型让它模仿」的差别：

- **逐字或没有。** 原子的原话、单元的全文、技能里引用的作者句子，都必须是来源文件的逐字子串，脚本核；不过不进下一步。改写过的引文比没有更糟，它让人以为那是作者说的。
- **两层分开。** 档案层最大化还原，工作集最小化激活——技能运行时按编号只读当下要判的那几条。
- **作者的方法就是方法。** 不评判对错、不加提醒、不拿行业通则补作者没讲的步骤；作者自己说的条件与「慎用」连同方法一起保留。

### amb-paoding

`amb-paoding` 把「作品变写作技能」拆成六段，门槛同样是产物在、脚本核过、输入哈希没变：

```text
一批作品（朋友圈 / 短视频转写 / 直播实录 / 课程 / 公众号）
   ↓  P1 盘点   →  每种形态多少篇、够不够出技能   ← 长课程先问你要什么；极短篇问收不收
   ↓  P2 入库   →  原件库：每篇逐字、带编号
   ↓  P3 聚类   →  同一形态内按结构聚成几种类型   ← 你看类型卡，定名字与取舍
   ↓  P4 写法书 →  每类型一份：魂 / 读者账 / 暗线 / 结构 / 劲儿 / 开头·中间·结尾
   ↓  P5 成技   →  每类型一个技能 + 路由器，体检；再对裸模型轻验收
   ↓  交付      →  自包含成品箱（技能 + 原件库 + 写法书 + 事实核对脚本）
        ↺  P6 增量：同形态补进类型；新形态料够另出技能、不够只存原件
```

写法书是原件与技能之间的拆解层，运行时技能读的就是它。每个大段（开头 / 中间 / 结尾）下的小段都写七行：明面写什么、暗地要达成什么、凭什么能达成、你要有什么才能借、句式、范文原文块、气口。三条底层规则：

- **魂要有证据。** 「他怎么看事」每条至少两篇不同原文作证，形容词不算；单篇范文型放宽到一篇并在说明里写明。
- **事实不搬。** 范文里的人名、数字、行业、地名、产品一个都不许进使用者的稿；技能只借结构、句式和看事的位置。缺的事实标〔待补〕，不编。
- **凭什么先问。** 技能向使用者要身份、领域、立场；答不上来就如实说这一类写出来会像壳，不硬写。

## 已知限制

`amb-beiming`：

- **冲突时跟作者。** 使用者的条件和作者主张相反时，它走作者的方法，不会自行换路。
- **料薄的任务仍可能单开成一个技能。** 语料里只讲过一两次的任务也会被切出来单独成技能，拿到手会觉得偏薄。撑不住就删掉它。

`amb-paoding`：

- **缺事实时偏保守。** 使用者没给的事实它不编、停下来要；在盲评里「事实贴合」远高于裸模型，但「成品可用」略低——裸模型会编出一条能直接念的稿。想要它先交整稿再问，可以在会话里直接说。
- **同形态才聚类。** 公众号和短视频不会归进同一个类型；一批料里形态很杂时，每种形态都要各自够篇数才出技能。
- **长形态不切环节。** 直播实录、课程整篇按一个原件处理，不拆成开场 / 讲解 / 互动各段单独拆解。

## 项目结构

```text
ambskill/
├── skills/
│   ├── amb-beiming/        语料 → 技能工具箱（SKILL.md + references + scripts + assets + evals）
│   └── amb-paoding/        作品 → 写作技能（SKILL.md + references + scripts + assets）
├── .claude-plugin/         Claude Code 插件市场定义
├── docs/                   README 里用到的图片（社群二维码）
├── README.md               本文件
├── AGENTS.md               仓库与协作约定
└── LICENSE
```

本机蒸馏工程默认建在 `<项目>-workspace/`，由你自己建、不进 Git——干净克隆里没有它，也带不走任何语料和成品。
