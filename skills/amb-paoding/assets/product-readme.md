## 目录与安装

```
${toolbox}/
  README.md
  skills/
    ${prefix}/                        路由器（只有 SKILL.md）：先判形态，再判类型
    ${prefix}-<形态>-<类型>/          类型技能：SKILL.md + references/pattern.md（写法书）+ references/originals/（范文全文）+ scripts/fact_check.py
  scripts/fact_check.py             与各技能自带的同一份（开放资产）
  kb/originals/                     全部原件，逐字，带编号（开放资产；技能运行不读它）
  kb/packs/                         每个类型的写法书、覆盖表
```

1. 把 `skills/` 下的每个目录整个拷进你的宿主技能目录（目录名就是技能名）。类型技能自带它要读的 `references/`；路由器按 `../${prefix}-<形态>-<类型>/SKILL.md` 相对路径指向同级技能，所以几个技能要放在同一个父目录下。
2. 说不清该找哪个，先调用 `${prefix}`（路由器）：它先问你要做哪种（朋友圈 / 短视频 / 直播 / 课程…），再问哪一类。
3. 每个类型技能开头三行写了：它替你写什么、你要先给什么、你会拿走什么。按它的「事实清单」把你的事实先给全——它不会用样例里的事实替你填。
4. 技能自带范文全文（`references/originals/`），每一段写的时候都会先读一篇范文的对应段再落笔；你也可以让它按编号读任何一篇整篇。原件太多的类型只带样例那几篇，其余在 `kb/originals/`。
5. 交稿前可用 `python3 <技能目录>/scripts/fact_check.py <回答.md> <技能目录>` 机械查一遍数字类事实是不是都来自你的事实清单（退出码 0 无可疑、1 有可疑、2 没找到清单）。

## 边界

- 技能借的是结构和句式，不是对方的事实。样例里的人名、数字、行业、地名不会写进你的稿；你没给的事实它写〔待补〕或追问，不编。
- 它复刻的是这一类内容的写法，不是某个人的判断，也不替任何人发声。
- 生成与验收都是模型完成；能不能发，要你用过才知道。用得不顺的地方记下来，是下一轮增量的输入。
- 只用公开且你有权使用的内容拆；成品是你自己的创作辅助，不冒充来源人发布。
