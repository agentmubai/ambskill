## 这个技能要做到什么

使用者带着方向和事实来，技能写出来的那一条，要像**这个人站在旁边替他写的**——不是像这一类，是像这个人。所以技能运行时的顺序是：先按写法书的魂想清楚「他会怎么看这件事」，再按小段写，写完对着魂自检。结构和句式是手段，魂是目的。

## 写 `${skill_dir_out}/SKILL.md`

严格按 `${spec_path}` 的节序。要点：

- frontmatter：`name: ${skill_name}`；`description` 一句话写「使用者带着什么来、拿走一条什么」，用使用者会说的触发词（「帮我写一条……」），不写类型编号、不写来源人名。
- 开头三行：写给使用者——这个技能替你写什么 / 你要先给什么 / 你会拿走什么。
- 紧接着一行**警示**（原样写）：「警示：范文里的人名、数字、行业、地名、案例、产品，全是来源人的，一个都不能进你的稿。写法书和范文只借他怎么看事、每段要达成什么、结构与句式。」这是全篇最核心的一条，放在纪律之前。
- 交付纪律：规约第 3 节各条，每条一行。**必须含**：先成为他再动笔；默认只交一版；事实不搬（只借句式与结构）；句式不整篇搬（同一篇范文的句式一条成稿里最多借两三处，范文型除外）；references 按小段定位读取。
- **先成为他（Phase 0a）**：让技能在收事实之前先读 `references/pattern.md`「怎么看事」与「读者账」两章，并对这次要写的事答两组：作者侧三句——他会先注意什么？他替谁说话？他想让读者带走哪一句？读者侧五问——读者为什么会停下来、我能帮他什么、他为什么要看这个、为什么看我的不看别人的、看完为什么会被种草。答案写在成稿前面的内部备注里（交付时删）。魂逐条引用（原话逐字 + 编号）；读者账把写法书的五问搬过来并写明「这次写的这条怎么答」。
- 事实清单（Phase 0b，F01…）：使用者必须提供的事实，逐条；**其中必须有「凭什么」类的项**——从写法书每小段「你要有什么才能借」汇总：使用者的身份 / 年限、他真懂的领域、他站哪一边、他手里有什么例子或事实。缺了追问，不用写法书里的事实补。凭什么答不上来的，技能要如实说「这一类你写出来会像壳」，再决定写不写。
- 骨架：一张成品骨架表——按写法书「结构」章：大段 / 小段 / 干什么 / 读写法书哪一小段。
- 写法：**每个小段一个 Phase**，Phase 号 = 小段号。每个 Phase 写：读（`references/pattern.md 第 N 小段`）/ 暗（这段要达成什么，从写法书「暗」搬）/ 看（清单里哪些事实）/ 用（哪几条句式——**逐字引用**「原话」（编号），怎么换）/ 照（先读这一小段「例」里范文的原文整段）/ 写实（成立怎么写、事实不足怎么写：〔待补：…〕或追问）/ 气口（这段怎么换气，从写法书搬）/ 交（这一步交出什么）。术是「候选无」的小段写「按这一段的暗和例写，不套句式」。写法书里标了「可循环」的小段，Phase 写明「按使用者的料转 N 轮，每轮结构同这一段、内容换一个」。
- 不归这里：相邻类型接手的情形——带什么去 `../<相邻技能目录>/SKILL.md`、判据一句、何时回来。
- 来源与边界：写明这是**这一类、这个人**的写法，不是他的判断，也不代表他本人；他的事实、案例、数字不进使用者的稿。
- 交付前自查：两层。**魂四问 + 读者一问**——有没有站错边、有没有讲道理代替说破、结尾有没有变成任务、有没有用了他从不用的词（从写法书「禁区」搬）、读者看完凭什么被种草；**事实核对**——每个事实句对回 F 编号 /〔待补〕，数字类用 `python3 <本技能目录>/scripts/fact_check.py <回答.md> <本技能目录>`。**都是交付前自己做的，不进交给使用者的正文**；成品末尾只留一行「需要核对来源就说一声」。

## 禁写

- 过程用语（本轮、执行者、子代理、工程、P1–P6）；免责句；本机绝对路径；「根据情况选择合适的结构」这类空话。
- 把写法书「例」里的人名、数字、行业、地名当使用者的事实。
- 并排给两版让使用者自己挑。
- 用形容词概括魂（「真诚」「有温度」）代替逐条引用。

## 交稿前自检三问（答案写进报告）

1. 分支问：使用者带一条典型需求来，先成为他那三句答得出来吗？哪个 Phase 接住它？接不住的算不算这一类？
2. 出处问：随机挑三条引文回原件核编号与原话；有一条改写了就全篓重核。
3. 像他问：把来源人名蒙掉，按这份技能写出的东西，熟悉他的人能认出是他的路数吗？认不出，看是魂没搬进来还是暗线没进 Phase。

## 写 `${report_out}`
