# 成品规约：类型技能与路由器长什么样

写技能的子代理必须先读本文件；`lint_product.py` 按本文件逐项体检。这里写"每节写什么、为什么"，骨架在第 5 节。

成品技能要做到的一件事：使用者带方向和事实来，写出来的那一条像**这个人站在旁边替他写的**。所以技能先成为他（魂），再按小段写（明 / 暗 / 凭什么 / 术 / 例 / 气口），写完对着魂自检。结构和句式是手段。

## 1 一个类型技能的目录

```
<prefix>-<形态>-<类型id>/
├── SKILL.md
├── references/
│   ├── pattern.md       写法书：怎么看事（魂）/ 暗线总览 / 结构 / 劲儿 / 开头 / 中间 / 结尾（每小段七行，「例」是范文该段原文整段）
│   └── originals/       范文全文：写法书「例」点到的篇永远带；本类型总量不超上限就全带
└── scripts/fact_check.py
```

技能运行时只读自己的 references，并且**按小段定位读取**：SKILL.md 里写 `references/pattern.md 第 3 小段`、`references/pattern.md「怎么看事」`、`references/originals/o01_004.md`，模型据此只读那一块。禁写"按需读取 references"。

## 2 SKILL.md 节序（固定，lint 按此查）

1. **frontmatter**：`name` = 目录名；`description` 一句话"使用者带着什么来、拿走一条什么"，用使用者会说的触发词，不写类型编号、不写来源人名。
2. **开头三行**（写给使用者）：这个技能替你写什么 / 你要先给什么 / 你会拿走什么。
   紧接一行**警示**（原样）：「警示：范文里的人名、数字、行业、地名、案例、产品，全是来源人的，一个都不能进你的稿。写法书和范文只借他怎么看事、每段要达成什么、结构与句式。」全篇最核心的一条，lint 查。
3. **交付纪律**（见第 3 节，每个技能都带）。
4. **先成为他（Phase 0a）**：从写法书「怎么看事」逐条搬魂（原话逐字 + 编号），从「读者账」搬五问；写明动笔前对这次的事答两组——作者侧三句（他会先注意什么？他替谁说话？他想让读者带走哪一句？）、读者侧五问（读者为什么会停下来？我能帮他什么？他为什么要看这个？为什么看我的不看别人的？看完为什么会被种草？）。答案写成内部备注，交付时删。
5. **事实清单（Phase 0b）**：使用者必须提供的事实，逐条编号 F01…。**必须含「凭什么」类的项**（从写法书每小段「你要有什么才能借」汇总：身份 / 年限、真懂的领域、站哪一边、手里的例子或事实）。缺了追问，不用写法书里的事实补。凭什么答不上来，技能如实说"这一类你写出来会像壳"。
6. **骨架**：一张成品骨架表——大段 / 小段 / 干什么 / 读写法书哪一小段（`references/pattern.md 第 N 小段`）。
7. **写法：Phase 1…N**（Phase 号 = 写法书小段号，≥ 2）。每个 Phase：读（`references/pattern.md 第 N 小段`）/ 暗（这段要达成什么）/ 看（清单里哪些事实）/ 用（哪几条句式——**逐字引用**「原话」（编号）并写清哪几个字换成使用者的事实）/ 照（先读这一小段「例」里范文的原文整段）/ 写实（成立怎么写；事实不足写〔待补：…〕或追问，追问不替代成品）/ 气口（这段怎么换气）/ 交（这一步交出什么）。术「候选无」的小段写"按这一段的暗和例写，不套句式"。写法书标了「可循环」的小段，Phase 写明"按使用者的料转 N 轮，每轮结构同这一段、内容换一个"。
8. **不归这里**：相邻类型接手的情形——带什么去 `../<prefix>-<形态>-<类型>/SKILL.md`、判据一句、何时回来。
9. **来源与边界**：写明这是**这一类、这个人**的写法，不是他的判断，也不代表来源人本人；来源人的事实、案例、数字不进使用者的稿。**范文型**还要写明"只有一篇范文，写出来会很像它，结构之外的变化没有依据"。
10. **交付前自查**：两层。魂四问 + 读者一问——有没有站错边、有没有讲道理代替说破、结尾有没有变成任务、有没有用了他从不用的词、读者看完凭什么被种草；事实核对——每个事实句对回 F 编号 /〔待补〕，数字类用 `python3 <本技能目录>/scripts/fact_check.py <回答.md> <本技能目录>`。**都是交付前自己做的动作，不进交给使用者的正文**；成品末尾只留一行「需要核对来源就说一声」。

## 3 交付纪律（写进每个技能）

- 先成为他再动笔：读「怎么看事」，答三句，再收事实、再排结构。
- 默认只交一版：按最可能成立的写实，交一条完整成稿；另一种可能与待补写在末尾附注。不并排给两版让使用者自己挑。
- 事实不搬：写法书里的人名、价格、行业、地名换成使用者事实清单里的对应项，没有就〔待补〕，不把来源人的事实抄过去。
- 句式不整篇搬：同一篇范文的句式在一条成稿里最多借两三处，其余段按「暗」和「例」用自己的话写——借的是他怎么看事、每段要达成什么，不是把一篇换词重念。范文型技能除外（它本来就是照着一篇写）。
- 凭什么先问：使用者答不出身份、领域、立场，如实说会像壳，不硬写。
- 事实不足写〔待补：xxx〕，不编。追问不替代成品：能出的部分先出。
- references 按小段定位读取（第 N 小段、「怎么看事」、原件编号），不整读。
- 核对是交付前的自查，不进正文；末尾留一行「需要核对来源就说一声」。

## 4 路由器

目录 `<prefix>/SKILL.md`，无 references。三节必有：

- **先判形态**：表 `| 使用者会怎么说 | 形态 |`；不确定先问这一句。
- **再判类型（路由表）**：同形态下 `| 使用者会怎么说 | 归哪个技能（相对链接 ../<prefix>-<形态>-<类型>/SKILL.md）| 判据 |`；模糊请求的追问模板；越界请求（不是这几种形态、或要的是对方的判断而不是写法）怎么答：说明不归本套技能，不硬答。
- **交付后导航**：交出一条之后，使用者接着最可能要什么，去哪。

每个类型技能都要出现在路由表里。路由器不写写法细节，不写来源人名。

## 6 禁写

- 过程用语：本轮、执行者、子代理、工程、P1–P6、按需读取。
- 免责句：此为编者归纳、不冒充、非作者原话。
- 本机绝对路径；`work/` 路径；指向技能目录外的链接（路由器指向同级技能除外）。
- "根据情况选择合适的结构"这类没有条件与动作的句子。
- 用形容词概括魂（真诚、有温度、有洞察）代替逐条引用。
- 把写法书里的人名、数字、行业、地名当使用者的事实。
- 来源人名（成品只说类型；「来源人几位」可写）。

## 7 体检项对照（lint_product.py）

frontmatter 有 name/description 且 name = 目录名；开头有警示行（范文里的具体内容不能进稿）；有「交付纪律」且写明先成为他、默认只交一版、没把并排两版当默认、事实不搬；有「先成为他」一节且含 ≥ 2 条带编号引文、「三句」与读者五问（停 / 帮 / 看我 / 种草）；有「事实清单」与 F01 且含「凭什么」；有「骨架」一节；Phase ≥ 2 且每个 Phase 点名 `pattern.md 第 N 小段`、含句式引文（编号）或写明「候选无」、含「暗」行；Phase 里有槽位或追问；有「不归这里」；有「来源与边界」并写明不是某人（范文型另写明只有一篇范文）；有自查且含魂四问关键词（站错边 / 说破 / 任务 / 从不用）与「种草」、写明不进正文、末尾留一行；写明按小段定位读取；自带 references/pattern.md、originals/ 非空与 scripts/fact_check.py；SKILL.md 点到的 originals 文件都在；SKILL.md 与 pattern.md 引文逐字且编号正确；无过程用语；无免责句；无绝对路径；相对链接可解析；正文 ≥ 3KB。路由器：引用全部类型技能、无悬空链接、有形态一级与路由表、有导航、≥ 1KB。
