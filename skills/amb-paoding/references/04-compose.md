# 04 P5 成技：类型技能与路由器

## 目标与产出

把每个类型的写法书变成一个能直接调用的写作技能：使用者带方向和事实来，技能先成为他（魂），再按小段写（暗 / 术 / 例 / 气口），写完对着魂自检，交一条像他写的成稿。再写一个路由器：先判形态，再判类型。

产出：`work/draft/skills/<prefix>-<形态>-<类型>/{SKILL.md, references/pattern.md, originals/, scripts/fact_check.py}`、`work/draft/skills/<prefix>/SKILL.md`（路由器）。完成 = lint 全 PASS 且记录未过期。

## 动作

1. `paoding.py compose <形态-类型|all>`：为每个类型建草稿目录、复制写法书与范文全文、复制 fact_check.py、生成写技能提示词（check 没过的类型会被拒）。派子代理，一类型一个。
2. 全部回来后 `paoding.py compose --router` → 派一个子代理写路由器。
3. `paoding.py lint`：逐项体检（节序、纪律、事实清单、骨架表、Phase 引文、样例点名、交接、边界、自查、引文逐字、自带文件、禁词、链接、体量）。FAIL 项写在行尾，交回子代理改，直到全 PASS。
4. 你抽读一个技能的 Phase：每段是不是真点了句式原话、写实那一句是不是"用这些句式写完"而不是"再填槽"。

## 规则

- 技能骨架、节序、每节写什么、交付纪律、禁写在 `product-spec.md`，lint 按它查；这里只写原则。
- 先成为他（Phase 0a）：从写法书「怎么看事」逐条搬魂，动笔前对这次的事答三句（先注意什么 / 替谁说话 / 带走哪一句）。事实清单（Phase 0b）必须含「凭什么」类的项，从写法书每小段「你要有什么才能借」汇总；答不上来如实说会像壳。
- 每个 Phase 对应写法书一个小段：读第 N 小段 / 暗（要达成什么）/ 看哪些事实 / 用哪几条句式（逐字 + 编号）/ 照（先读例里范文该段整段）/ 写实 / 气口 / 交什么。术「候选无」的小段写「按这一段的暗和例写」。
- 成品要重范文也要有魂：例是范文该段整段，魂是他跨篇的选择。lint 查先成为他一节有引文和三句、事实清单含凭什么、每个 Phase 点小段且有暗行、自查含魂四问、originals/ 非空。
- 默认只交一版：按最可能成立的写实，另一种可能与待补写在末尾附注。不并排让使用者挑。
- 事实不搬：样例与句式里的人名、数字、行业、地名换成使用者事实清单里的对应项；没有就〔待补〕。这是交付纪律里必须有的一条，lint 查。
- 范文全文按**类型**带，不按形态：写法书「例」点到的篇永远带；本类型成员总量 ≤ 100 KB 就全带；超了只带样例篇，其余留成品根 `kb/`，SKILL.md 写明「其余原件在生成它的工程里」。类型文件可用 `bundle: all | samples` 强制。
- 范文型技能：写法就是「照着这一篇的每一段写」；边界节必须写「只有一篇范文，写出来会很像它，结构之外的变化没有依据」，lint 查。
- 路由器先判形态再判类型；每个类型技能都要在路由表里；越界（不是这几种形态、或要的是对方的判断）说明不归这套技能。
- 辨识度：把类型名蒙掉，读者要能从骨架与句式里认出这是哪一类写法；每段换成别的类型也成立就是通用写作课。

## 依据

外层：先成为他再写——视角与立场决定每一段怎么落；认知负荷——运行时只读当下要写的那一小段，不整读写法书。

内层（可观察）：
1. lint 全 PASS；SKILL.md 与 references 的引文逐字且编号正确。
2. 每个 Phase 有句式引文或「候选无」。
3. 交付纪律含默认一版、事实不搬、按编号读取三句。

为什么这样定：
- 先成为他：同样的事实，站错边、说教代替说破、结尾变任务，结构对了也不像他。魂进 Phase 0a 并进自查，是「像这个人」而不只是「像这一类」的保证。
- Phase 必须点小段、有暗行：判断对了、正文像讲义，是同仓 amb-beiming 四次实测里成品可用为负的一个来源；每段知道要达成什么、对着范文该段写，正文才像。
- 事实不搬写进纪律并由 lint 查：拆对方的料，这条不能只靠子代理自觉。
- 按类型总量定全带还是只带样例：amb-beiming 实测过整篇案例库全进运行时答不完、新题更差——那是几十万字的课程案例。真正的变量是这一个类型有多少篇、多大：十几条朋友圈加起来几 KB 全带没问题，六十条两千字的短视频转写就该挑；四节短课全带也行。形态只是代理，所以不按形态判。

## 常见失误

- Phase 里写"参考 references/pattern.md"却不点第几小段：等于让模型整读。
- 先成为他一节把魂写成形容词：lint 查引文数，但形容词 + 一个编号也能混过——你抽读时看是不是选择句。
- 把样例卡里的行业当默认场景写进成稿。
- 路由器写了写法细节：那是类型技能的事。
- lint 报引文不符就改 references 里的原话去凑：references 是拆解层复制来的，改它等于改证据；该改的是 SKILL.md 里抄错的那句。
- compose 之后又改了写法书：lint 记录变 stale，`compose --sync-refs` 同步后重 lint。
