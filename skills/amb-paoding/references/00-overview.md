# 00 总纲：这套流水线是什么、产什么、怎么记状态

SKILL.md 是调度表，本文件是它背后的契约：术语、三层产物、工程目录、类型文件 schema、状态与停止、派发方式。执行任何一段之前先读完本文件；之后按 SKILL.md 调度表定位到 01–06。

## 1 目标

输入一批作品（朋友圈、短视频转写、直播实录、课程录播、公众号、文案——同一形态或混合形态，可来自不同人），输出一套写作技能：每个「形态 × 类型」一个技能，加一个路由器。使用者带自己的事实来，拿走一条按这类结构写好的成稿。

拆什么形态，出什么形态。炼的是**结构与写法**，不是来源人的判断。

## 2 术语

| 词 | 指 |
|---|---|
| 执行 agent | 读 SKILL.md、调度脚本、派子代理、写给使用者看的文档的那个 agent（你） |
| 子代理 | 执行 agent 派出去读原件、聚类型、抽骨架、写技能、答题、评分的 agent；一份提示词一个 |
| 使用者 | 提供作品、确认类型、最后用技能的人 |
| 来源人 | 作品是谁的（`author`）。默认是对方——对标账号、想学的人；也可以是使用者自己 |
| 形态 | 朋友圈 / 短视频 / 直播 / 课程 / 公众号 / 文案 / 其他。形态决定「一篇」的单位与起手骨架 |
| 原件 | 一篇作品的逐字全文，带编号 `oGG_FFF`（组两位 + 文件三位），文件头记来源人 / 形态 / 标题 |
| 类型 | 同一形态下按结构聚出来的一类写法（不是按话题）；`形态-类型id` 是技能的唯一键 |
| 写法书 | 一个类型的拆解层 `pattern.md`：他怎么看事（魂）/ 要达成什么（暗线）/ 结构 / 劲儿 / 开头 / 中间 / 结尾；每小段 明 / 暗 / 凭什么 / 你要有什么才能借 / 术 / 例 / 气口 |
| 覆盖表 | 每个成员原件被写法书引用几处；零引用篇要有处置 |
| 工程 | 一次生产的全部中间物与成品所在目录 `<项目>-paoding/` |
| 成品 | `product/<箱名>/`：路由器 + 类型技能 + 开放资产（原件库、拆解层、事实核对脚本） |

## 3 三层产物

| 层 | 放哪 | 是什么 | 折损 |
|---|---|---|---|
| 原件库 | `work/kb/originals/` | 每篇原模原样逐字存，脚本从文件生成，子代理不抄、不改字 | 零 |
| 拆解层 | `work/kb/packs/<形态-类型>/` | 写法书 + 覆盖表 + 处置。每条引文与每个例块逐字 + 原件编号，脚本核；魂每条 ≥ 2 篇证据 | 有，但可审计 |
| 技能层 | `work/draft/skills/` → `product/` | 写法书 + 范文全文（例篇永远带；本类型总量 ≤ 100 KB 全带）。技能先成为他，再按小段写，写完对着魂自检 | 拆解可折损，范文不折损 |

为什么三层：只留拆解会把原文压没，新料无法对照、引文无法核。成品要**重范文**：仿写靠整篇范文摆在眼前，骨架与句式是拆解、是让人看懂结构，范文才是参考的主体。带多少按类型的总量算，不按形态：几 KB 的一类全带，几十篇长转写的一类只带样例篇，其余留原件库按编号调。

## 4 六段一览

| 段 | 做什么 | 完成的定义 | 使用者参与 |
|---|---|---|---|
| P1 盘点 | 按形态分组、篇数、来源人；写预检报告 | catalog 在；预检报告有结论（可开工 / 收缩 / 补料） | 看结论 |
| P2 切篇 | 一篇一原件进原件库 | index.jsonl 在，ingest 记录 ok | 无 |
| P3 聚类型 | 同形态内按结构聚 3–8 类；类型卡 | `work/types/<形态>.json` 含 confirmed_at，confirm 记录 ok | **确认类型名与取舍（唯一参与点）** |
| P4 写法书 | 每类型一份写法书 + 覆盖表 | check 记录 ok：章齐、魂有证据、引文与例逐字、零引用篇已处置 | 无 |
| P5 成技 | 每类型一技能 + 路由器 | lint 全 PASS | 无 |
| 轻验收 | 对裸模型盲评一套题 | 矩阵完整，report 在（不设通过线） | 看报告 |
| 交付 | 装配成品 | deliver 记录 ok | 拿走 |
| P6 增量 | 新篇只入原件库，按三档处理（同形态正常增量 / 新形态够料出新技能 / 新形态不够只存），只重拆受影响类型 | 同上各门槛重新 ok | 类型有增删时再看一眼 |

使用者只在 P3 出场一次。P1 的预检结论要给他看，但不需要他动手；轻验收报告是给他看的，不是门。

## 5 工程目录

```
<项目>-paoding/
├── work/
│   ├── catalog.json          P1：组、稳定文件号、形态、来源人
│   ├── project.json          prefix（技能目录前缀，默认 pd）、toolbox
│   ├── meta.json             各阶段校验记录（时间、通过、输入哈希）；status 据此判"完成"
│   ├── pipeline.md           流水账
│   ├── STOP                  存在即"停止中"
│   ├── prompts/              脚本填好的提示词，一份一个子代理
│   ├── reports/              子代理写的报告；外部 CLI 的回复
│   ├── docs/                 给使用者看的：预检报告、类型卡-<形态>、验收说明
│   ├── types/<形态>.json     P3：类型定义（使用者确认后）；<形态>.draft.json 是子代理草案
│   ├── kb/originals/         原件库：<编号>.md + index.jsonl
│   ├── kb/packs/<形态-类型>/ pattern.md + coverage.md + dispositions.json + mismatch.md
│   ├── draft/skills/         P5 草稿技能
│   └── tests/<题集>/         questions.md answers/ packets/ key.json scores/ scores.json report.md
└── product/<箱名>/           成品：README.md skills/ scripts/fact_check.py [kb/]
```

`survey` 第一次运行时建好全部目录。作品不拷进工程，catalog 记来源路径；原件是它的逐字副本。

## 6 类型文件 schema（`work/types/<形态>.json`）

```json
{"form": "短视频", "confirmed_at": "2026-01-01T12:00:00（使用者确认后才填；空则 confirm 拒绝）", "user_note": "使用者确认时说的话，原样记",
 "types": [{"id": "hook", "name": "反常识开头", "brief": "一句话：这类怎么写", "members": ["o01_001", "o01_004"], "thin_ok": false, "exemplar": false}],
 "unassigned": {"o01_009": "为什么不归任何类型"}}
```

- `id` ASCII 短名，技能目录名 = `<prefix>-<形态>-<id>`。
- 一篇只归一个类型；本形态每篇要么在某类型里、要么在 `unassigned` 里带理由。
- 篇数少于参考线（默认 15；直播 / 课程 6）的类型要 `thin_ok: true` 才不被提醒——出不出薄技能由使用者定。
- `bundle`（可省）：`all` 强制带全部成员全文，`samples` 强制只带样例篇；不写按总量自动判。
- `exemplar: true` = **范文型**：使用者点名某一篇写得特别好，单独做成「照着这一篇写」的技能。members 恰好一篇，`user_note` 必须有他的原话（confirm 查）。魂、暗线、术、例都只从这一篇出；技能的边界节写明「只有一篇范文，写出来会很像它」。

## 7 状态、完成与停止

- **完成** = 产物文件存在 + 对应校验脚本记录通过（meta.json）+ 记录时的输入哈希与现在一致。三者缺一，`status` 都不显示"完成"。子代理的口头汇报不算数。
- 校验脚本：`confirm`（P3）、`check`（P4）、`lint`（P5）、`tally` / `report`（验收）、`deliver`。输入变了（改了写法书、加了原件）依赖它的记录显示 stale，重跑那一步即可。
- **停止**：`paoding.py stop` 写 `work/STOP`，所有生成提示词的脚本读到它就拒绝。没有批次销账表：停止只管不再派新的；已派出的等其返回，回来后照常核验。恢复 `recover`。
- 接手任何工程先跑 `status`。

## 8 派发方式

| | 宿主能派子代理 | 宿主不能派子代理 |
|---|---|---|
| `PAODING_AGENT=none`（默认） | 脚本生成提示词，你一份派一个子代理 | 你自己按提示词逐份做；先告知使用者将串行处理 |
| `PAODING_AGENT=codex\|claude\|custom`（只设 `PAODING_AGENT_CMD` 等于 custom） | 脚本生成后直接并发调用外部 CLI（`--workers`） | 同左 |

自定义命令契约：提示词从 stdin 进，回复写 stdout（存 `work/reports/<名>.reply.md`），非 0 退出码算失败；输出含 usage limit / quota 类字样算额度用尽；429 歇两分钟重试。回复不是产物，提示词里指定的文件才是。

## 9 与同仓 amb-beiming 的关系

两扇独立的门，共用零件不共用流程。amb-beiming：使用者**自己的**课 / 访谈 → 替自己做具体任务的分身（他怎么判、怎么做）。amb-paoding：**对方的**任意形态作品 → 同形态的复刻技能（这类怎么写）。同一份课程两条路不同：想让它替自己判断做事 → amb-beiming；想照它的结构做一门自己的课 → amb-paoding。触发词互斥写在各自的 `description` 里。
