# 01 P1 盘点与 P2 切篇

## 目标与产出

把一堆文件变成"哪几种形态、各多少篇、够不够出技能"的一页结论，交给使用者看；然后把每篇原模原样存进原件库。

产出：`work/catalog.json`（脚本）、`work/docs/预检报告.md`（你写）、`work/kb/originals/<编号>.md` + `index.jsonl`（脚本）。完成 = 预检报告含结论词（可开工 / 收缩 / 补料）+ ingest 记录 ok。

## 动作

1. 向使用者拿三样：作品目录；一句"这是谁的"（来源人；多人就按子目录分）；一句"你想拿它写什么"（粗方向即可）。作品不拷进工程。
   **料里有课程、直播这类长内容时多问一句：你要的是什么？** 想学他讲课 / 直播的那个感觉、照他的结构做自己的一门课或一场直播 → 本技能。想让它替自己判断、做事（「按他的方法帮我定价 / 选品 / 写方案」）→ 那是用自己的料炼分身的事，推荐同仓 amb-beiming，不硬做。答案写进预检报告。
2. `python3 <skill>/scripts/paoding.py survey --corpus <作品目录> --project <项目>-paoding [--author g01=某某]`。脚本建工程目录、按子目录分组、给每文件稳定编号、猜形态、打印规模表：每个形态多少篇、够不够。
3. 看形态猜得对不对。错的 `--form g02=短视频` 重跑，只改形态不动编号。来源人没标的 `--author` 补上。
4. 抽读 3–5 篇看：是文本不是乱码；是对方本人的作品不是二手转述；同一形态的篇之间写法是不是同构（结构反复出现），还是每篇一个样。
5. `paoding.py ingest`：一篇一原件，逐字。看打印的篇数与形态分布。
6. 排除清单写进预检报告：转不了的、明显无关的、重复的，每条写理由。**极短篇**（`survey` 把不到 40 字的单列）不自动排除：几十个字没头没尾，多半拆不出开头 / 中间 / 结尾，问使用者收不收，利弊说清——收，这一类的结构会模糊一点；不收，移出作品目录。他定。
7. 写预检报告（模板见下），交使用者看结论。`cluster` 会查预检报告有没有结论，没有就拒绝。

## 规则

- 一篇的单位按形态定：朋友圈一条、短视频一条、直播一场（或一段完整环节）、课程一节、公众号一篇。都是一文件一篇；一个文件里塞了多条的，让使用者先拆文件。
- 篇数为主、字数为辅：同一形态下单个类型 ≥ 15 篇才出技能；直播 / 课程放宽到 ≥ 6。不足给"表达样品"，不给技能。总字数不当门槛——20 条朋友圈字数很少，照样能看出结构。
- 同构性是先于一切的判断：同一形态聚不出 ≥ 2 个稳定类型，直说"料不一致，做不成"。多形态混进来按形态分组各自判，不混。
- 多人料必须标来源人；成品写明"这是类型，不是某人"。
- 只用公开且使用者有权使用的内容；成品是他自己的创作辅助，不冒充来源人发布。预检报告要把这句写给他看。
- 预检结论只有三种：可开工 / 收缩（只做某几个形态）/ 补料（缺什么、补多少）。不写"建议考虑"。
- 原件正文由脚本生成：短视频 / 直播 / 课程转写从第一个说话人段起（跳过平台导出的元数据行）；朋友圈 / 公众号 / 文案取全文。子代理不参与这一步。

## 依据

外层：结构主义的类型学——同一形态内反复出现的段落结构才是类型；话题不是。饱和判断沿用扎根理论——抽读到新篇不再出现新结构，料才算够。

内层（可观察）：
1. 预检报告结论是三者之一，并附排除清单（转不了的、不是本人的、重复的）。
2. catalog 里每文件有三位号，`survey --update` 后旧号不变；原件编号终身稳定。
3. `index.jsonl` 篇数 = catalog 文本文件数 − 空正文跳过数。

为什么这样定：
- 稳定编号：技能里的引文按编号回原件，重排会让全部引文失效。
- 篇数不看字数：短形态天然短，字数门槛会把最适合拆的料挡在门外。
- 脚本切篇：整篇逐字抄是机械活，交给模型会漏、会顺。

## 模板

`work/docs/预检报告.md`（对使用者写，用"你"）：

```
# 预检报告

## 结论：可开工 | 收缩（只做 <形态>）| 补料（缺 …）

## 你给的料
<形态> <篇数> 篇，来源人 <谁>；<形态> …。总共 <N> 篇。

## 你要的是什么
<学他讲课 / 直播 / 写文案的路数，照着做自己的 → 这套工具对；想让它替你判断做事 → 不是这套，见下一节>

## 太短的篇
<N> 篇不到 40 字：<列出>。它们拆不出开头中间结尾。收进来这一类的结构会模糊一点，不收就当没有。你定。

## 每种形态能不能出
| 形态 | 篇 | 写法是否同构 | 预计几个类型 | 够不够 |

## 我不打算收的
- <文件 / 组>：<原因>（转不了 / 不是本人 / 重复 / 残篇）

## 你要知道的两件事
- 拆出来的是这类内容的写法，不是来源人的判断，也不代表他本人。
- 只拆公开且你有权使用的内容；成品是你的创作辅助，不冒充他发布。

## 下一步
我先把每篇原样存好，再按结构聚类型给你看。你只需要在类型出来后看一眼、定名字。
```

## 常见失误

- 按话题分组当形态：形态是朋友圈 / 短视频这种载体，不是"减脂 / 育儿"。
- 一个文件塞几十条朋友圈就当一篇：编号只有一个，句式回不到具体那一条。让使用者先拆。
- 忘了标来源人，到成品才发现分不清谁的：成品只能写"类型"，但预检时就该问。
- 用总字数说"手写更便宜"：短形态篇数够就够。
- 把二手转述（别人写的"某某说过"）当原件。
