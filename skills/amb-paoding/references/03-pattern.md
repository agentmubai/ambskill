# 03 P4 写法书：把那个人蒸出来

## 目标与产出

把一个类型的全部成员蒸成一份写法书：他怎么看事（魂）、每段明面写什么 / 暗地要达成什么 / 凭什么能达成、读起来什么劲儿、每小段带范文该段的原文整段。成品技能运行时读的就是它。**不是拆结构，是让那个人站到使用者面前替他写。**

产出（每类型 `work/kb/packs/<形态-类型>/`）：`pattern.md`（子代理）；`coverage.md`、`mismatch.md`（脚本）；`dispositions.json`（你，用 dispose 写）。完成 = check 记录 ok。

## 动作

每个类型按顺序（不同类型之间可并行）：

1. `paoding.py pattern <形态-类型>`（要求该形态 confirm 通过）→ 派子代理写写法书。
2. `paoding.py check <形态-类型>`：章齐、魂有证据、三大段与小段七行、引文与例块逐字、覆盖表。看 `mismatch.md` 与 `coverage.md`。
3. 不过的交回子代理改（把 FAIL 行与 mismatch.md 给它），再 check，直到 PASS。魂条证据不足最常见——让它回原件找第二篇证据，找不到就删那条。
4. 零引用篇逐篇处置：`paoding.py dispose <形态-类型> <编号,…> --as 并入|排除|补拆 --note …`。
5. `check` 通过时会顺手产 `work/docs/写法书摘要-<形态-类型>.md`（魂 + 读者账 + 结构，去掉编号）——给使用者瞄一眼「他怎么看事」像不像，不设门、不加参与点；他说不像就改写法书，不重拆。篇数 < 5 的类型摘要开头会写「魂只是轮廓」。
6. 你抽读写法书的「怎么看事」与任意一个小段：魂是不是选择句不是形容词；「暗」是不是真说出了目的；「凭什么」是不是他真有的东西；「例」是不是原文整段。

## 规则

- 写法书八章固定（标题含关键字即可）：**怎么看事**（魂）/ **读者账** / **要达成什么**（暗线总览）/ **结构** / **劲儿** / **开头** / **中间** / **结尾**。三大段固定，小段按料来，编号全书连续；**中间至少两个小段**——三大段定位置（对着读者的停 / 看 / 种草），功能在小段。
- 小段可标「可循环」：**结构循环**——同一小段的走法在一篇里转几轮，每轮装的内容不同（公域直播的讲品 → 互动 → 催单，一轮换一个品），不是找内容一样的段落。≥ 2 篇范文有证据才准标。循环是料里看出来的，不按形态预设——私域直播可能没有，课程多半没有。
- 极短篇（几十个字、没头没尾）拆不出三大段：预检就该问使用者收不收；收进来的类型，结尾小段允许写「与开头合并」。
- 读者账是暗线的另一面：作者要达成什么，得靠读者愿意。五问固定——他为什么会停下来 / 我能帮他什么 / 他为什么要看这个 / 为什么看我的不看别人的 / 看完为什么会被种草——每问带证据（编号）并标落在哪个小段；答案落到 ≥ 3 个原件（范文型 ≥ 1）。任何内容背后都在答这五问，答不出来的那一问，成品那一段多半是空的。
- 每小段七行固定：**明**（明面写了什么）/ **暗**（真正要达成什么）/ **凭什么**（他有什么让这段成立）/ **你要有什么才能借**（使用者手里要有什么）/ **术**（可套句式，逐字 + 怎么换）/ **例**（范文该段原文整段，引用块 + 编号）/ **气口**（这段怎么换气）。可加「变体」「〔事实，不搬〕」。
- 魂每条写成「他会……而不是……」的选择句，≥ 2 个不同原件的证据，≥ 3 条。只有一处证据的是那篇的选择，不是他的；一条证据都没有的是形容词，不许写。另列「禁区」：他从不做的事。
- 暗不是形容目的，是说清这一段要让读者发生什么（点头 / 翻转 / 带走一句），以及为什么放这儿；凭什么不是夸他，是他有什么（年限、积累、立场、手里的事实）；你要有什么才能借，是使用者拿不出这个时该怎么办。
- 例是原文**整段**，不是摘一句；说话人行、时间戳不抄；脚本核对时也跳过它们。
- 术里人名、数字、行业、地名是事实不是句式；某小段真没有可套句式写「候选无」并在例里说明。
- 范文型（exemplar）：魂从一篇里能看出多少写多少，写不满三条如实标；每小段例都是它。
- 增量（`pattern --update`）只补新成员：魂与暗线有新证据就加编号，能归进已有小段的加例与术，确实是新小段再加并重排编号。不改旧措辞、不删旧内容。

## 依据

外层：明暗两线——一篇内容明面上是结构与句子，暗地里是每一段要让读者发生什么，以及作者凭什么做得到；魂是跨篇重复的选择。拆到暗线和魂，仿写才不是壳。

内层（可观察）：
1. `check` 八章都在、魂 ≥ 3 条且每条 ≥ 2 篇证据、读者账五问都答且落到 ≥ 3 个原件、每小段七行齐。
2. 「」引文与例块逐字命中 100%，编号绑定正确。
3. 覆盖表零引用篇全部有处置。

为什么这样定：
- 魂要两篇证据：模型很擅长给一个人贴形容词；要它在两篇里找出同一个选择，才逼它读，也才拦得住空话。
- 例整段跟着小段走：写第几段就看别人第几段，不用抱全文找；整篇留原件库按编号调。
- 凭什么单列：他能这么写是因为他有东西；使用者没有那个东西，光学形就是壳。这一行直接变成成品技能向使用者要的「凭什么」。
- 逐字核跳过说话人行：转写每隔几句一行标签，不跳过就没法引整段。

## 模板

写法书的结构由 `assets/prompts/pattern.md` 规定，这里不重复。`dispositions.json`：

```json
{"o01_009": {"as": "排除", "note": "重复上传的同一条", "at": "…"},
 "o01_012": {"as": "并入", "note": "结构是 story 类，改 types 后重 confirm", "at": "…"}}
```

## 常见失误

- 魂写成形容词（「真诚」「有洞察」）：check 会因证据不足拦下；让子代理回原件找两篇里同一个选择。
- 暗写成明的复述（「这段引出话题」）：目的要说到读者身上——让他点头、让他翻转、让他带走什么。
- 读者账写成作者的自夸（「我很专业所以他看我的」）：要写读者那边的理由——他此刻的处境、他为什么信这个人、他看完得到了什么。
- 凭什么写成夸奖（「她很专业」）：要写他有什么——年限、积累、手里的事实。
- 例只摘一句：那是术。例是整段。
- 段数按起手模板凑齐：料里没有「催单」段就不该有。
- 零引用篇直接从 members 里删掉了事：那是改类型，要走 dispose 并入 + confirm，留下记录。
- 手改 coverage.md 的处置：重跑 check 会覆盖；处置只经 dispose 写进 dispositions.json。
