# amb-paoding

把对方的作品蒸成写作技能，拆什么形态出什么形态：一批朋友圈拆成写朋友圈的技能，一批短视频转写拆成写脚本的技能，一批直播实录拆成直播流程稿的技能，一门课拆成「做一门这种课」的技能。按结构聚成几种类型，每个类型一份写法书，一个技能，加一个路由器。使用者说一个方向、给一点事实，拿走一条像那个人站在旁边替他写的成稿；每条引文都能按编号回到原件原文。

这是一个 Agent Skill：给能读 `SKILL.md`、能跑 Python、最好能派子代理的 agent 宿主用。人只出场一次：看聚出来的类型、定名字与取舍。

蒸的是这个人怎么写——他怎么看事、每段要达成什么、凭什么、怎么说、什么劲儿——不是他的生意判断。写法书里的魂每条要两篇以上证据，形容词不算；「凭什么」会变成技能向你要的东西：你的身份、你真懂的领域、你站哪一边。答不上来，技能会如实说这一类你写出来会像壳。

## 装

整仓安装见仓库根 README。只拿这一套时，把本目录整个放进宿主的技能目录，目录名保持 `amb-paoding`。只要 Python 3.9+ 标准库。

```
<宿主技能目录>/amb-paoding/
├── SKILL.md          执行 agent 读的调度表
├── README.md         本文件（给人）
├── LICENSE
├── references/       00 总纲、01–06 各段、product-spec 成品规约
├── assets/           prompts/ 7 份提示词模板；product-readme.md 成品 README 模板；fact_check.py 复制进每个技能的事实核对
└── scripts/          paoding.py 入口 + 一功能一脚本
```

## 三分钟上手

准备一个作品目录（子目录 = 一组，最好一组一个形态或一个来源人；文本文件 .txt/.md/.srt/.vtt；短视频、直播、课程先转写），然后在宿主里对 agent 说：

> 用 amb-paoding 把 `<作品目录>` 拆成写作技能，工程放 `<项目>-paoding/`。这是 <谁> 的 <什么形态>。

它会先跑：

```
python3 <本目录>/scripts/paoding.py survey --corpus <作品目录> --project <项目>-paoding --author g01=<谁>
python3 <本目录>/scripts/paoding.py ingest --project <项目>-paoding
python3 <本目录>/scripts/paoding.py status --project <项目>-paoding
```

`survey` 打印每种形态多少篇、够不够出技能；`ingest` 把每篇原样存进原件库；`status` 打印六段的完成情况与下一步命令。之后 agent 按 SKILL.md 推进；聚出类型时它会停下来让你看类型卡、定名字。

想自己一步步跑，`python3 scripts/paoding.py help` 列出全部子命令，每个脚本头部有用法与"为什么有这一步"。

## 你会得到什么

`<项目>-paoding/product/<箱名>/`：

- `skills/<前缀>/SKILL.md` 路由器：先问你要做哪种（朋友圈 / 短视频 / 直播 / 课程…），再问哪一类。
- `skills/<前缀>-<形态>-<类型>/` 类型技能：SKILL.md + references/pattern.md（写法书：他怎么看事、每段要达成什么、凭什么、句式、范文该段原文、气口）+ references/originals/（范文全文）+ scripts/fact_check.py；单独拷走一个也能工作。技能先成为他，再按小段写，写完对着魂自检。
- `kb/originals/` 全部原件，逐字、带编号（开放资产，技能运行不读它；增量的输入）。
- `kb/packs/` 每个类型的写法书与覆盖表。
- `README.md`：给拿到成品的人。

成品自包含，把 `skills/` 下的目录拷到任何宿主的技能目录即可用；不会自动装进任何地方。

## 三条底线

- **原件不折损。** 每篇原模原样存，脚本生成。拆解层折损可以，但覆盖表算出每篇被引几处，零引用篇要有处置。
- **逐字或没有。** 写法书里的每条引文、每个例块，技能里的每条引文，都是原件的逐字子串并带编号，脚本核。魂每条要两篇以上证据，形容词不算。
- **事实不搬。** 对方作品里的人名、数字、行业、地名不进你的稿；只借结构与句式。

## 与同仓 amb-beiming 的分界

按「料是谁的 + 拿走什么」分：你自己的课 / 访谈，想让它替你做具体的事 → amb-beiming；对方的任意形态作品，想照它的结构写自己的 → amb-paoding。同一份课程两条路不同。

## 派发方式

默认（`PAODING_AGENT` 未设）：脚本生成提示词，执行 agent 一份派一个子代理；宿主不能派子代理时它自己逐份做。也可让脚本直接并发调用外部 CLI：`PAODING_AGENT=codex`、`PAODING_AGENT=claude`，或只设 `PAODING_AGENT_CMD="<命令>"`（提示词从 stdin 进，回复到 stdout，非 0 算失败；`{out}` 替换为回复文件路径）。单次调用超过 `PAODING_AGENT_TIMEOUT`（默认 1800 秒）会被终止。`work/STOP` 存在时不开新任务。

## 开发验证（维护者）

改了本目录任何文件后：

```
python3 scripts/paoding.py selfcheck [--corpus <某次真实作品目录>]
```

它查死链、外部路径、禁词、语料泄漏、提示词槽位契约、01–06 节序、编译、体积。然后拿一小批真实作品走一遍 P1–P4，确认 `confirm`、`check` 的退出码与报告仍成立；有成品时跑 `lint`。

## 已知限制

- 直播、课程这类长形态目前一文件一篇，不在文件内再切环节；环节结构由聚类型的子代理在骨架里写出来。
- 多人料聚出来的类型是"这类怎么写"，不是任何一个人的写法；写法差异大的多人料会聚不出稳定类型，预检会直说。
- 轻验收不设通过线，只出差距报告；能不能发，要你用过才知道。
