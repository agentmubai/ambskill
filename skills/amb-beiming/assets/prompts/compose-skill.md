## 写 `${skill_dir_out}/SKILL.md`

严格按 `${spec_path}` 的节序（frontmatter → 开头三行 → 交付纪律 → 道 → 器·事实清单 → 法 Phase 1…N → 器·逐句来源表与事实核对 → 本任务不判的问题 → 势 → 说话风格）。要点：

- frontmatter：`name: ${skill_name}`；`description` 一句话写"使用者带着什么来、拿走什么"，用触发词（使用者会怎么说这件事），不写方法名。
- 开头三行：写给使用者看的——这个技能替你判什么、你要先给什么、你会拿走什么。
- 道：从 layers.md 的道逐条搬，原话引用块逐字、原子 id 照抄；"它决定了什么""语料没覆盖时怎么推"照抄或改写得更可执行。
- 器·事实清单（Phase 0）：使用者必须提供的事实，逐条；缺了就追问，不用常识补。
- 法：每个 Phase 四段——看清单里哪些事实 / 按哪条道判 / 成立怎么做、不成立怎么做（分支写全）/ 这一步交付什么。分支里点名 `references/methods.md M??` 与 `references/cases.md u.._.._..`（按编号定位读取，不写"按需读取"）。作者的手法用作者原话逐字（术），标原子 id。
- 信息不足时写槽位句（〔待补：xxx〕）或追问，不用行业通则填。追问不替代成品：能出的部分先出。
- 器·逐句来源表与事实核对：交付前把成品里每个事实句对回使用者给的事实或作者的判断；数字、规则类事实提示用本技能自带的 `scripts/fact_check.py`（写法：`python3 <本技能目录>/scripts/fact_check.py <回答.md> <本技能目录>`；它已在 `${skill_dir_out}/scripts/`）。
- 本任务不判的问题：每条写 带什么去 / 作者那句判断（原话逐字 + id）/ 何时回来。交接对象用相邻技能的目录名。
- 势：外部条件，从 layers.md 搬；无则写"无，语料未涉及"。
- 说话风格（人）：作者怎么说话——句式、常用比喻、语气；逐字摘 3–5 句（标 id），并写一句"技能输出时保留哪几点"。

## 禁写

- 过程用语（本轮、执行者、子代理、工程、S1–S9）；免责句（"此为编者归纳""不冒充作者"）；本机绝对路径；"根据情况选择合适的框架"这类空话。
- 方法论以外的判断。作者没讲过的，就写"作者未涉及，按道 D? 推：……"，不用行业通则替。
- 案例卡里的具体事实当使用者的事实。

## 交稿前自检三问（答案写进报告，不是走过场）

1. 分支问：使用者带一个典型问题来，SKILL.md 的哪个 Phase 的哪条分支会接住它？接不住的问题算不算本任务的？答不上就补分支或写进"本任务不判"。
2. 出处问：随机挑三条"按他说的"引文，回原子库核 id 与原话；有一条改写了就全篓重核。
3. 辨识度问：把作者名蒙掉，读者能从道与术里猜出这是谁的方法吗？如果每条道换成别的老师也成立，说明写成了行业通则——回知识包找作者独有的判断替换。
