## 目录与安装

```
${toolbox}/
  README.md
  skills/
    ${prefix}/                 路由器（只有 SKILL.md）
    ${prefix}-<任务>/          任务技能：SKILL.md + references/{methods,cases,layers}.md + scripts/fact_check.py
  scripts/fact_check.py      与各技能自带的同一份（开放资产，方便单独调用）
  kb/                        原子库、单元库、各任务知识包（开放资产；技能运行不读它）
```

1. 把 `skills/` 下的每个目录整个拷进你的宿主技能目录（每个目录一个技能，目录名就是技能名）。任务技能自带它要读的 `references/` 与它要跑的 `scripts/fact_check.py`，只拷一个技能目录也能独立工作；路由器只有 `SKILL.md`，它按 `../${prefix}-<任务>/SKILL.md` 相对路径指向同级任务技能，所以几个技能要放在同一个父目录下。
2. 根目录的 `scripts/` 与 `kb/` 不是运行依赖，不装进宿主也不影响技能；留在这里是给人查原话、做检索或增量更新用。
3. 说不清该找哪个技能，先调用 `${prefix}`（路由器），它会告诉你归哪个、要带什么。
4. 每个任务技能开头三行写了：它替你判什么、你要先给什么、你会拿走什么。按它的"事实清单"把你的事实先给全——它不会用行业常识替你编。
5. 技能交稿前会做逐句来源核对；数字类事实可在宿主技能目录里用 `python3 <技能目录>/scripts/fact_check.py <回答.md> <技能目录>` 再机械查一遍（回答里要有「事实清单」一节；退出码 0 无可疑、1 有可疑、2 没找到清单）。

## 边界

- 技能只用作者讲过的判断；作者没讲过的情形，它会写明"按哪条根判断推"，不会替你编方法。
- 案例卡里的人名、数字、行业事实只用来解释判断，不会当成你的事实写进稿里。
- 生成与验收都是模型完成；真正的效果要你用过才知道。用得不顺的地方记下来，是下一轮增量更新的输入。
