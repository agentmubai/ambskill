# 05 S5 蒸馏：知识包、案例库、六层、案例卡、索引

## 目标与产出

把每个任务池变成技能能直接引用的知识包：方法论（模块 M01…）、案例对照与案例库、六层（道法术证器势）、案例卡、索引。六层的原话必须逐字，这是 S5 的硬门槛。

产出（每任务 `work/kb/packs/<任务>/`）：`methods.md`、`case_map.md`（子代理）；`case_library.md`、`case_library_full.md`（脚本）；`layers.md`、`cards.md`（子代理）；`work/kb/layers_input/<任务>/`（脚本候选与核对结果）；`work/kb/index.md`。完成 = 四件齐、每任务 check-layers 记录通过、index 在。

## 动作

每个任务按顺序（不同任务之间可并行）：

1. `beiming.py distill <任务> --step pack` → 派子代理写 methods.md 与 case_map.md。脚本打印池体量；超过约 400 KB（约 15 万字）会提示把原子按文件拆两半分两次派，第二次带上第一次的 methods.md 续写。
2. `beiming.py caselib <任务>`：脚本按 case_map 逐字生成案例库（精选）与全量。
3. `beiming.py screen <任务>`：脚本粗筛道/术候选、原理线索、势候选、证表、命中单元。
4. `beiming.py distill <任务> --step layers` → 派子代理写 layers.md（只能从候选里选原话）。
5. `beiming.py check-layers <任务>`：逐字核对道/术/势，并核标了原子 id 的原话确实属于那条 id（"原话曾存在"与"出处写对"是两回事）；cards.md 已在时也核卡里标 unit_id 的引文是不是该单元 text 的逐字子串；道或术 0 条、任务池为空都记未完成，不算通过。不过 → 把 `mismatch.md` 交回子代理改，再核，直到 0。
6. `beiming.py distill <任务> --step cards` → 派子代理写 cards.md → 再跑一次 `check-layers <任务>`（核卡里的引文）。
7. 全部任务做完 `beiming.py index`：每个任务要有 ≥ 1 个 M 模块、≥ 1 张卡、道 ≥ 1 条、check-layers 记录通过，否则索引写出但 S5 不算完成（退出码 1）。
8. 你抽读每个任务的 layers.md 的道：3–6 条、每条有"它决定了什么"与"没覆盖时怎么推"、原话确实是判断句不是例句。

## 规则

- 六层各是什么：**道** 作者的根判断（无条件主张，跨来源反复出现，决定其他判断）；**法** 判断 → 动作的流程（按模块顺序）；**术** 具体手法、句式、数字（逐字）；**证** 法 → 案例的对应（只用来选法和解释，不进使用者的稿）；**器** 使用时必须核对的事实类别与核对方法；**势** 外部条件（平台规则、时间、行业变化）。层名固定，不换词。
- 道只从脚本候选里选：模型自己找的"道"多半是它自己的总结。候选里没有的，写进报告由你判断是否补进候选。
- 去重四类：完全重复留一；同义合一、依据列全；层级包含挂到上位；表面相似实为条件不同的分开写并写清条件差。
- 方法论的每条主张都要能回到 ≥ 2 条原子 id；补充过渡语可以有，但"主张"不能是原子池里没有的。
- 案例库全文只在知识库；技能运行时读 cards.md。卡里的具体事实标明"不能搬进使用者的稿"。
- 外源原理（作者引用的经典理论）与作者自己的判断分开标。
- 六层核对不过不许 compose；compose 脚本会检查 check-layers 记录。

## 依据

外层：Toulmin 论证模型——每个方法模块 = 问题 / 成立条件 / 分支 / 步骤 / 例外，与原子的四要素是同一个模型；哈佛案例教学法——案例本身不教，"它解释哪条判断"的教学笔记才教。

内层（可观察）：
1. `check-layers` 道 / 术 / 势的原话逐字命中 100%，且标了 id 的原话属于那条 id；道、术都不为 0 条。
2. 每个模块的依据行 ≥ 2 条原子 id（与规则节"每条主张回到 ≥ 2 条原子"及 distill-pack 提示词一致；语料里只讲过一次的写进"单证主张"，不做模块）；case_map 每个模块至少一个单元，一个单元可对多个模块（分多行，脚本保留全部对照）。
3. 成品只带精选案例库，全量不进。

为什么这样定：
- 道从候选选：粗筛候选来自原子库；模型"自由归道"写出来的多是它对方法论的概括，原子库里没有对应原话。
- 案例库不进运行时：把整个档案带进运行时等于全部激活，模型会从里面借细节填使用者的稿。
- 证不进稿：案例只用来选法和说明为什么；卡里的主体、数字属于案例主体，不属于使用者。

实测参照（上一版记录）：一次归层里两个任务约九成的术被改写成了通顺句，与原文对不上（当时没有逐字核对这一步，这是 check-layers 的来历）；带全量案例库（0.3–1.5 MB）答题跑不完，换精选后能答完；把整段案例与作品全部带进运行时的版本，在新题上反而输给了薄的版本，换成案例卡 + 事实清单后赢回来。

## 常见失误

- 没跑 screen 就派 layers：子代理没有候选，自己造道。
- check-layers 报"来自本任务池外"就去删：那是通过但提示，说明该原话在别的任务池；要看的是"不符"那一栏。
- 一个任务 pack 还没回来就跑 caselib：case_map 为空，精选为空，证表为空——要按顺序。
- 术写成书面陈述：术的价值是作者的原句式与数字，书面陈述是 knowledge 字段的事。
- 为跨来源"同观点不同措辞"单跑向量去重：贵且抓不准；语义去重就在 pack 这一步由读完整个池的子代理折叠。
- 因 skills 标签归得偏宽就把整批退回重标：pack 按领域聚焦时会剔除漏进来的原子，知识包仍干净；只在池里异物过半时才回 S4 改 match。
- 势为空不说明原因：是语料没提，还是被筛掉了？报告里要写；语料真没提就在层里写"无"。
