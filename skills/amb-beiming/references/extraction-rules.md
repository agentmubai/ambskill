# 萃取规则（原子与单元）

本文件是萃取子代理读的规则本体。S2 第一次试点时它被复制为工程的 `work/docs/执行提示词.md`，之后的校准补丁只追加到那份副本末尾并升版本；本文件保持为初版 v1.0。写规则的原则：每条都能在产物上检查，每条都说明防什么。

## 1 两种产物

**单元**先切，**原子**后抽。原子擅长保"判断"，天然丢"完整体"：上一版实测 5,578 条原子只覆盖原文 10.6% 的字符，一条短视频稿进原子层只剩 3 条各 50 字的碎句。所以先把文件里的完整体切成单元逐字保存，再在单元里和单元外抽判断。

### 1.1 单元 schema（`units_bNNN.jsonl`，一行一个）

```json
{"unit_id": "u01_003_02",
 "type": "case | work | sop | argument",
 "title": "一句话标题",
 "text": "原文连续子串，不限长，逐字",
 "source": {"group": "组名", "file": "文件名", "timestamp_start": "可选", "timestamp_end": "可选"},
 "speaker": "主要讲述者", "role": "讲师 | 嘉宾 | 学员 | 主持 | 作品 | 未知",
 "summary": "三句以内：背景 / 做法 / 结果（有数字带数字；没结果写「未提供结果」）",
 "atom_ids": ["c01_003_012"]}
```

- **case**：一个学员 / 门店 / 账号的完整案例段（背景 → 做法 → 结果 → 作者点评），作者中途插话也包含在内。允许没有结果：现场问题 → 诊断 → 改法也成 case。
- **work**：作者自己的一条完整作品（短视频稿、文章、朋友圈、销售信）。形态 D 的文件一文件一个 work：`text` 由脚本从文件正文生成（从第一个说话人段起，平台导出的时间、时长、Keywords 等元数据行不在内），派发时已预写进 units 文件；抽取者只补 `summary`、`speaker`、`atom_ids`，不改 `text`。非 D 形态里出现的作者作品仍由抽取者作为 work 单元逐字保存。
- **sop**：作者连续讲完的一套步骤（第一步…直到收尾），或有明确输入、维度、选择、产出的操作框架。
- **argument**：一段完整论证（结论 → 理由 → 例子 → 回扣）。分类教学若每类形成 定义 → 机制 → 示例 → 边界 的闭环，各自独立成 argument，不因有"第一第二"就判 sop。
- 课程里被反复暂停、点评的嵌入作品不拼成 work；保存含引介、播放、讲评的连续 case 或 argument。
- `timestamp_end` 取单元内最后一个转录段的起始标签；没有精确时间就不造。
- 一篇 2 万字课程通常 3–8 个单元；一个 case 通常 300–3000 字。

### 1.2 原子 schema（`atoms_bNNN.jsonl`，一行一条）

```json
{"id": "c01_003_012",
 "knowledge": "书面语完整陈述句，含成立条件；原文有数字就带数字",
 "original": "逐字原话，≤200 字，不含说话人标签与时间戳",
 "source": {"group": "组名", "file": "文件名", "timestamp": "可选", "title": "可选：original 抄的是文件名标题时填"},
 "speaker": "谁说的", "role": "讲师 | 嘉宾 | 学员 | 主持 | 作品 | 未知",
 "topics": ["主题白名单里的类目"], "skills": ["分池标签"],
 "type": "principle | method | case | anti-pattern | insight | tool",
 "claim_scope": "无条件主张 | 有条件做法 | 举例",
 "confidence": "high | medium | low",
 "flags": [], "unit_id": "可选：从哪个单元抽出", "note": "可选：抽取者自己的话"}
```

- **id**：`c{组号两位}_{文件号三位}_{序号三位}`，组号与文件号按提示词给的，序号在文件内从 001 起。
- **topics**：开工前由执行 agent 按候选任务草案定一套 10–20 类主题白名单写进本文件第 6 节；名称来自语料本身。抽取中有内容无处归，加类目并在 note 写"新增类目"。
- **skills**：候选任务列表里的标签，只是分池用；最终任务在方案阶段才定。case 类原子额外挂一个案例检索标签（如 `cases`）。
- **type**：knowledge 的形态——principle 原则判断 / method 做法 / case 案例主体的做法与结果 / anti-pattern 作者明说不要做的 / insight 观察与洞见 / tool 文本里实际观察到的编排、句法、模板。口述的操作建议按 method，实际看到的句法结构才按 tool。
- **claim_scope**：只记作者怎么表述，不记重不重要。当普遍真理讲（"一定""所有""永远"）→ 无条件主张；某种情况下怎么做 → 有条件做法；在举某家店、某条视频 → 举例。type 记形态，claim_scope 记表述方式，两者独立。归层时道的候选靠它，不靠正则猜。
- **flags**：`platform` = 作者自己说这与平台规则有关（只是事实标注，不隔离不改写）；`conflict` = 与同来源其他说法数字或结论矛盾，两条都留并在 note 互相指向；`unverified` = 说话人的自述数字无法核实；`title` = original 抄的是文件名里的标题（正文里没有），核验按标题核。没有"灰色 / 争议"标签，抽取者不评判方法对错。
- **note**：抽取者的话只能放这里（不确定归属、疑似口误、与前文矛盾、规则边界问题）。knowledge 与 original 里不能出现抽取者的评价、提醒、修正。

## 2 质量红线

1. 一个原子 = 一个可独立成立的知识点。写完按四要素自检：主张（knowledge）/ 依据（original）/ 条件（什么情况成立）/ 例外（什么情况不成立）。缺条件降 medium，缺依据不成原子。宁缺毋滥：一篇 5 万字讲稿合理产出 15–40 条。
2. 独特性：没听过这套语料的聪明人说不出来的才要。行业常识（"内容要垂直""坚持就有结果"）不单独成原子；作者把常识当某个方法的前提条件讲时，并进那条方法的 knowledge。作者反复强调的常识照抽，note 写"反复强调"。
3. claim_scope 按第 1.2 节判，只有看着上下文的抽取者能做，切成原子后找不回来。
4. knowledge 写法：书面语完整陈述句、含成立条件。非 case 类禁止以"某人认为 / 主张 / 把 X 归结为"开头（speaker 字段已有归属）；case 类以案例主体开头。
5. 案例必须带主体：谁、做什么、结果如何。有数字带数字，没数字不编不推算；纯履历只在解释方法可信度时收一条汇总。
6. 去重：同说话人同文件内反复讲的只出一条，取表达最完整处。
7. 落不到动作或判断的内容不抽（情绪渲染、励志表态、纯哲学感慨），不按题材判：同一段里作者说出「怎么做 / 什么情况下这样做」的部分照抽。
8. original ≤ 200 字（settle 按同一上限判，超了整批 failed），逐字保留口语；knowledge 重写为书面语。original 不含说话人标签与时间戳（"Speaker 1 00:02:46"这种转录头不进 original）。
9. 逐字读完全文再抽，禁止只读开头、禁止用搜索代替通读；超长文件分段读完，段间回看前 500 字。
10. 说话人判定不信 Speaker 编号：同一编号段内可能先学员自述后作者点评，同一编号跨段可能换人，不建全局身份字典。以自报身份、称呼关系、作者的播放 / 点评动作为准；判不出写未知。角色按片段功能：课程里播放的预录作品 role=作品；现场学员问答才 role=学员；现场外请讲者 role=嘉宾。作者说"我亲自采访了他"的他人数据仍是转述。
11. original 不跨转录头拼接：取单侧连续核心片段，note 标另一段时间戳；knowledge 可综合两段。
12. 枚举清单不按点数配额："19 个自查点"不等于 19 条原子，每项过独特性。
13. 画面 / 音频未见：镜头、光线、配乐这类转录里看不到听不到的，只抽作者说出口的判断和参数，note 标"画面/音频未见"。
14. 卖课段的取舍：纯动员、背书、报名、赠品、名额倒数不抽；卖课段里穿插的操作演示、逐句改稿、SOP 照抽。
15. 先切单元再抽原子，单元里抽出的原子回填 unit_id，单元的 atom_ids 列全；单元之外的零散判断照常抽。
16. 教学层和作品层分开：形态 D 的原子 role 写"作品"，同一方法在课程里讲的和在作品里用的各自成条，蒸馏阶段再对照。
17. 标题只在文件名里（短视频、帖子）时，要抽"标题怎么起 / 首句怎么写"的判断：`original` 逐字抄提示词列出的文件名标题，`flags` 加 `title`，`source.title` 填同一标题；核验按标题核。标题在正文里的不用这条。不许把标题与正文拼成一条 original。

## 3 保真红线

1. 原法的名称、方向、力度、态度不改写。作者说"引起恐慌"，knowledge 就写"引起恐慌"，不写成"风险提示的受限变体"。
2. 不做道德评判。作者教的方法就是方法：不打"争议 / 灰色"标签，不因抽取者觉得不妥就删、降级、改温和、加提醒。用不用由使用者决定。作者自己说的"慎用""只在什么情况用"是原法的条件，连同方法保留——"作者说慎用"与"抽取者建议谨慎"是两回事。
3. 四样东西分开放：原文（original）/ 作者主张（knowledge）/ 抽取者补充（note）/ 核验状态（flags）。任何一样混进另一样都是错。
4. 作者自己的纠正要保留：后面推翻或修正了前面的说法，两条都抽，后一条 note 写"修正 c.._.._.."。
5. 不用通用商业常识补作者没讲的步骤。作者只讲三步，knowledge 就是三步。
6. 标注不进正文：原法 / 归纳 / 补充的区分写在 note；knowledge 按顾问口气直接说，不写"此为编者判断"这类免责句。

## 4 confidence 判据

- **high** 两种依据：① 说话人谈自己亲历的业务 / 账号 / 交付，给出自己的数字或完整推导（访谈里嘉宾拆自己的生意也是第一手，不因访谈形式降级）；② 作者亲自完整演示的 输入 → 操作 → 输出（现场改稿、现场跑工具；转录里能识别 原稿 → 处理 → 新句 的口头改稿也算）。只有工具名或口号、只说"可以用某钩子"不算。作品层自述"这条我就是这么想的"不自动 high；转述别人的后台数据 medium，同一单元里其他条不连带升。
- **medium**：讲别人的案例、无数字的泛化经验、口播数字含混（保守写成区间或下限）、广告段的模型级内容。
- **low**：站不住但有记录价值。
- 数字前后矛盾 → 两条都留、都打 conflict、note 互指；不弃用（弃用会丢掉"作者自己也说不准"这个信息）。
- **不设占比配额**。上一版实测规则里写了"high 不超过 60%"，抽取者机械执行，后几批 high 掉到 0%，把嘉宾第一手数据也降成 medium。正向判据"自己做的 high，听来的 medium"就够；high 偏高是通病，验收报告注明即可，不用规则压。

## 5 数字五类

① 主体自述的经营数字 → high + `unverified`；② 示例槽位数字（"开了 5 年"）→ 不标，note 写"示例槽位"；③ 泛化效果数字（"100 条里 20 条带客"）→ medium + `unverified`；④ AI 输出里的数字 → note 写"AI 生成"，不当经营数据；⑤ 组合数、修辞数、脚本参数（"一万种组合""15 秒镜头"）→ 不标。所有数字在 original 里原样保留，knowledge 里不换算、不四舍五入。

## 7 形态要求

- **A 访谈**：分清访谈者与被访者；被访者拆自己的生意（人群、产品、渠道、定价、获客、复购等要素，按语料里实际讲到的抽，不凑齐）是第一手（high）；主持人只在给出自己的独立判断时抽，其提问与总结是转述（medium）。
- **B 单讲师课**：抽讲师；演示与答疑段是高价值段（方法在真问题上展开），暖场、寒暄、课程介绍不产原子；学员提问默认不抽，除非作者肯定了那个做法。
- **C 多讲师短分享**：每篇讲者不同，speaker 必填；重点是讲者的独家判断与经营数字（数字按第 5 节标）；开场自我介绍与背景不单独成原子，并入该讲者的汇总 case 单元；同一批里可能混进长访谈，按内容实际密度调产量，不死守条数区间。
- **D 作者作品**：一文件一个 work 单元（text 脚本预写，见 1.1），role=作品；原子抽作品里体现的判断与句法（tool）；作品的标题只在文件名里时按红线 17 抽。
