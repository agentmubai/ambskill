# 06 S6 成技：任务技能与路由器

## 目标与产出

把每个任务的知识包写成一个能被宿主直接调用的技能（SKILL.md + references 三件），再写一个路由器技能；全部通过成品体检。

产出：`work/draft/skills/<prefix>-<任务>/{SKILL.md, references/{methods,cases,layers}.md}`、`work/draft/skills/<prefix>/SKILL.md`（路由器）。完成 = lint 全 PASS 且记录未过期。

## 动作

1. `beiming.py compose all`：脚本检查每任务 check-layers 通过，复制知识包三件到草稿 references/、复制 fact_check.py 到草稿 scripts/，生成写技能的提示词。（S9 只想重新复制三件不重写技能：`compose <任务> --sync-refs`。）
2. 派子代理，一任务一个。它必须先读 `references/product-spec.md`。
3. 全部回来后 `beiming.py compose --router` → 派一个子代理写路由器。
4. `beiming.py lint`：逐项体检（节序、道的四要素、Phase 分支、槽位或追问、器两节、势、不判清单、说话风格、点名模块与卡、自带 references 与 fact_check.py、SKILL.md 引文逐字且与所标原子 id 一致、无过程用语、无免责句、无绝对路径、链接可解析、体量）。lint 记录的输入含 references/ 全部文件，之后改了任何一份都会变 stale。FAIL 项写在行尾，交回子代理改，直到全 PASS。
5. 你自己以使用者身份读一遍每个 SKILL.md 的开头三行与 Phase 1：能不能看懂"我要先给什么、会拿到什么"。再看子代理报告里"交稿前自检三问"的答案（分支问 / 出处问 / 辨识度问），第 3 问答不出"作者独有的那条是什么"的技能，是写成了行业通则，退回重写——这一条 lint 核不了，只有人读。

## 规则

- 技能的节序、每节写什么、禁写什么，全在 product-spec.md；lint 按它查。这里只列成技阶段的纪律。
- 技能运行时只读自己的 references，按编号定位（`references/methods.md M03`、`references/cases.md u01_003_02`）；禁写"按需读取"——那等于让模型整读。
- Phase 的分支必须写全"成立怎么做 / 不成立怎么做"；只有一条路的 Phase 不是判断，是步骤。
- 信息不足时用槽位句〔待补：…〕或追问；追问不替代成品，能出的先出。**默认只交一版**：按最可能成立的那条分支写实，交一份完整成品；另一条分支与待补事实写进末尾附注（「若 F0? 其实是…，把这几句改成…」）。不并排给两版让使用者自己挑——把选择推回给使用者的不算成品。
- 作者没讲过的情形写"作者未涉及，按道 D? 推：…"，不用行业通则填。
- 路由器双模式：任务前路由（怎么说 → 归哪个 → 判据；复合怎么拆；模糊怎么追问；越界怎么答）+ 任务后导航（交付后下一步去哪）。
- lint 过了不等于好，S7 才判好坏；lint 不过不进 S7。lint 不数交付纪律条数、不查 Phase 上限、体量下限能被填充行凑过——这些是既定口径，靠上面第 5 步的人读与 S7 兜。
- 辨识度：把作者名蒙掉，读者要能从道与术里猜出是谁的方法；每条道换成别的老师也成立就是通则。子代理交稿前自问三问（compose-skill.md），答案进报告。

## 依据

外层：产生式规则（IF 条件 THEN 动作）与自然决策模型——模型面对新任务时是"新手"，需要显式的"看到什么条件→做什么"；认知学徒制——把作者的隐性判断显性化为可点名的步骤。

内层（可观察）：
1. 每个 Phase 都有成立 / 不成立两个分支。
2. 引用块原话逐字且带原子 id。
3. `references/methods.md` 的 M 号与 `references/cases.md` 的 u 号被点名合计 ≥ 3 处，其中案例卡 ≥ 1（tasks.json 标了 `no_case` 的任务改为：写明「本任务无现场案例」且不引 cases.md）；lint 按同一口径查，全 PASS。

为什么这样定：
- 禁"按需读取"：它把"读什么"的决定交给运行时的模型，结果不是整读就是跳过；按编号点名把决定留在写技能的时候。
- 分支写全：只写"如果 A 则 B"的 Phase 在 A 不成立时没有出口，反转题必败。
- 追问不替代成品：每题都先问的技能在"成品可用"维拿不到分。
- 路由器双模式：任务前的意图和任务后的追问是两张表，只有一张就答不上另一半。

实测参照（上一版记录）：一版 12 个任务技能全部没有引用自己的 references（refs:0），知识包约七成内容在成品里没有入口；路由器在一轮验收里被漏测。

## 模板

技能骨架、开头三行、Phase 四段、不判清单、说话风格的写法在 product-spec.md 第 2–4 节。

## 常见失误

- 子代理没读 product-spec 就写：节序全乱，lint 一片 FAIL，来回改三次。
- 技能里引用 `work/kb/...`：成品拷出去就断；只能引用自己目录下的 references。
- 把六层原样贴进 SKILL.md：层是知识包的组织方式，技能要的是 Phase 里的判断与点名；六层放 references/layers.md。
- 免责句（"此为编者归纳"）：使用者不是来读免责的；判断的可信度靠原子 id 与原话，不靠声明。
- 路由器写了方法细节：那是任务技能的事，路由器只判归属与顺序。
