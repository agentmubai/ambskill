# 成品规约：任务技能与路由器长什么样

写技能的子代理必须先读本文件；`lint_product.py` 按本文件逐项体检。这里写的是"每节写什么、为什么"，骨架在第 5 节。

## 1 一个任务技能的目录

```
<prefix>-<任务id>/
├── SKILL.md
└── references/
    ├── methods.md   方法论（模块 M01…），来自知识包，不改内容
    ├── cases.md     案例卡（unit_id 点名），来自知识包 cards.md
    └── layers.md    六层（道法术证器势），已逐字核对
```

技能运行时只读自己的 references，并且**按编号定位读取**：SKILL.md 里写 `references/methods.md M03`、`references/cases.md u01_003_02`，模型据此只读那一段。禁写"按需读取 references"，那等于让模型整读三份文件然后遗忘主分支。

每个任务技能自带 `scripts/fact_check.py`（compose 与 deliver 复制同一份进去），技能里写 `python3 <本技能目录>/scripts/fact_check.py <回答.md> <本技能目录>` 提示使用者可机械核对数字；单独拷走一个技能目录也能跑。成品根另放一份同文件作开放资产，不是运行依赖。

## 2 SKILL.md 节序（固定，lint 按此查）

1. **frontmatter**：`name` = 目录名；`description` 一句话写"使用者带着什么来、拿走什么"，用使用者会说的触发词，不写方法名与编号。
2. **开头三行**（写给使用者）：这个技能替你判什么 / 你要先给什么 / 你会拿走什么。
3. **交付纪律**（5–7 条，见第 3 节，每个技能都带，措辞可按任务调整）。
4. **道**：3–6 条根判断（候选少就少，不凑）。每条：一句书面陈述作标题；`>` 引用块里作者原话逐字 + 原子 id；"它决定了什么"（在哪些 Phase 起作用）；"语料没覆盖时怎么推"。作者引用的外源原理（经典理论、别人的模型）从 layers.md 的"外源原理"表搬，另起 `### 外源原理` 放在道的末尾，与作者自己的判断分开标，不混进道条目。
5. **器·事实清单（Phase 0）**：使用者必须提供的事实，逐条编号 F01…；缺了追问，不用常识补。在这里写死槽位规矩（会改变结论、且从清单和作者句式推不出的才写成〔槽位〕，其余写实、句尾标"（可改）"）和缺关键事实时的默认动作：**默认只交一版**：按最可能成立的那条分支写实，交一份完整成品；另一条分支与待补事实写进末尾附注（「若 F0? 其实是…，把这几句改成…」）。不并排给两版让使用者自己挑——把选择推回给使用者的不算成品。
6. **法：Phase 1…N**（≥ 2 个，通常 3–5）。法的开头先给一张成品骨架表（最终交付长什么样、哪几段、每段来自哪个 Phase）。每个 Phase 四段：看清单里哪些事实 / 按哪条道判 / 成立怎么做、不成立怎么做（分支写全，条件 → 动作）/ 这一步交付什么。分支里点名 `references/methods.md M??`、`references/cases.md u??`；作者的手法（术）逐字引用并标原子 id，举例句不是术。信息不足写槽位句〔待补：…〕或追问。
7. **器·逐句来源表与事实核对**：交付前把成品里每个事实句对回 F 编号 /〔槽位〕/ 作者判断（模块号或道号），三者之外的句子删掉；数字类事实提示用 fact_check.py。**这是交付前你自己做的动作，做完不进交给使用者的正文**——终端宿主（Claude Code / Codex 等）不渲染 HTML，`<details>` 折不住，整张表会摊开糊在使用者眼前。成品末尾只留一行「需要逐句核对来源就说一声」；使用者开口要，再把表给他。
8. **本任务不判的问题**：每条三项——带什么去（相邻技能目录名 + 要带的事实）/ 作者那句判断（原话逐字 + id，说明为什么不归这里）/ 何时回来。接到这类问题先交接；作者的方法对它有看法也只说一句，不展开做。
9. **势**：外部条件（平台规则、时间、行业变化），从 layers.md 搬，每条写 原话｜原子 id｜来源与时间｜影响哪个 Phase｜什么变化算过期；开头一句"以下为语料当时的平台条件，现行规则以平台为准"。无则写"无，语料未涉及"。
10. **说话风格（人）**：作者怎么说话——句式、常用比喻、语气；逐字摘 3–5 句标 id；写一句"技能输出时保留哪几点"。

## 3 交付纪律（写进每个技能）

- 事实不足写槽位句〔待补：xxx〕，不编。
- 追问不替代成品：能出的部分先出，追问附在后面。
- **默认只交一版**：按最可能成立的那条分支写实，交一份完整成品；另一条分支与待补事实写进末尾附注（「若 F0? 其实是…，把这几句改成…」）。不并排给两版让使用者自己挑——把选择推回给使用者的不算成品。
- 行业通则不当作者的判断；作者没讲过的写"作者未涉及，按道 D? 推：…"。
- 对使用者点名作者的方法名，不说 M03 这种编号（编号只用于技能内部定位）。
- 核对是交付前的自查动作，不进交给使用者的正文；末尾留一行「需要核对来源就说一声」，他要才给。
- 使用者给的事实优先；与作者判断矛盾时先澄清再写，不悄悄改任何一边。
- 案例卡里的人名、数字、行业事实只用来解释判断，不进使用者的稿。
- references 按编号定位读取（methods.md 的 M 号、cases.md 的 u 号），不整读。

## 4 路由器技能

目录 `<prefix>/SKILL.md`，无 references。两节必有：

- **任务前路由**：表 `| 使用者会怎么说 | 归哪个技能（相对链接 ../<prefix>-<任务>/SKILL.md）| 判据 |`；复合请求的拆分顺序与"前一个产出怎么喂后一个"；模糊请求的追问模板；越界请求怎么答（说明不归本工具箱，不硬答）。
- **任务后导航**：每个任务技能交付后，使用者接着最可能要什么、去哪。

每个任务技能都要出现在路由表里。路由器不写方法细节。

## 6 禁写

- 过程用语：本轮、执行者、子代理、工程、S1–S9、按需读取。
- 免责句：此为编者归纳、不冒充作者、非作者原话。
- 本机绝对路径；`work/` 路径；指向技能目录外的链接（路由器指向同级任务技能 `../<prefix>-<任务>/SKILL.md` 除外）。
- "根据情况选择合适的框架"这类没有条件与动作的句子。
- 方法论以外的判断。

## 7 体检项对照（lint_product.py）

frontmatter 有 name/description 且 name = 目录名；道 ≥ 1 条且每条有引用块、原子 id、"它决定了什么"、"怎么推"；Phase ≥ 2 且每个有分支；有槽位或追问；交付纪律写明默认只交一版、且没把「并排给两版」当默认；核对写明是交付前自查、不进交给使用者的正文；点名了模块号或卡 id；器两节；势；不判清单三项；说话风格；证按 id 点名 ≥ 1，methods M 号 + cases u 号合计 ≥ 3；写明按编号定位；自带三份 references 与 scripts/fact_check.py；SKILL.md 引文逐字且属于所标原子 id（按任务池核）；无过程用语；无免责句；无绝对路径；相对链接可解析；正文 ≥ 3KB。路由器：引用全部任务技能、无悬空链接、两节都有。
