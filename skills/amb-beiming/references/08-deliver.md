# 08 S8 交付

## 目标与产出

把通过验收的草稿装配成一个自包含的成品目录，接收方拷走就能用。

产出：`product/<工具箱名>/`：`README.md`（写明目录布局与安装方式）、`skills/<prefix>/`、`skills/<prefix>-<任务>/`（各自带 references/ 与 scripts/fact_check.py）、根 `scripts/fact_check.py`（开放资产）、默认 `kb/`（原子库、单元库、别名、索引、来源索引、各任务知识包，不含案例库全量）、可选 `.claude-plugin/marketplace.json`。完成 = deliver 记录通过（含成品体检 `--product`）。

## 动作

1. 确认 status 显示 S6 完成；S7 至少一套题集 PASS，或验收报告已写明弱项且使用者要求带 `--force` 交付。
2. `beiming.py deliver <工具箱名> [--plugin] [--no-kb] [--dest <目录>] [--force]`。脚本复制草稿、写 README（按 assets/product-readme.md 填）、放 fact_check.py、附知识库、生成市场文件，然后跑 `lint --product`。`--force` 时成品 README 写明弱项，不写 `work/` 或其它工程路径。
3. 体检 FAIL（多半是成品里残留 `work/` 路径）→ 改草稿 → 重新 deliver。
4. 你以接收方身份读一遍成品 README：不看任何工程文件，能不能知道怎么装、先找哪个技能、要带什么来。
5. 把成品目录与验收报告一起交使用者。成品不进 amb-beiming 自己的目录，也不自动装进任何宿主。

## 规则

- 三个目录分清：工程目录（`<项目>-workspace/`，给生产者与下次增量）、成品目录（`product/<工具箱名>/` 或 `--dest`，给接收方）、amb-beiming 自己的目录（只有源码，谁都不往里放东西）。
- 成品只引用自己目录内的文件；README 与 SKILL.md 里不出现 `work/`、本机绝对路径、流水线段号。
- 默认附知识库：接收方能按 id 回到原话，增量时不必回生产工程；使用者明确不要（体积、保密）才 `--no-kb`。
- 案例库全量（case_library_full.md）不进成品：技能运行时不读它，接收方要看全文回知识库精选版即可。
- `--plugin` 只是多生成一个市场文件，不改变技能内容；接收方用什么宿主装由他决定。
- 成品 README 写给接收方，用"你"；工程术语一个不写。
- 交付纪律（写进每个技能、也写进 README 边界节）：槽位句而非编造；追问不替代成品；行业通则不当事实；点名作者方法名不写编号给使用者看；使用者的事实优先，矛盾先澄清。

## 依据

外层：成品按接收方视角组织——接收方只有成品目录，没有工程，所以成品必须自包含、可拆用。

内层（可观察）：
1. `lint --product` 通过：无 `work/`、无本机路径、路由器链接都指向存在的技能。
2. README 有装法、入口、边界三节。
3. 每个任务技能目录里有 `scripts/fact_check.py`；成品根另有一份。只拷一个任务技能目录到空目录，`python3 skills/<技能>/scripts/fact_check.py <回答.md> skills/<技能>` 能跑。

为什么这样定：
- 自包含：成品里任何指向工程的路径，到接收方那里都是断链。
- 附知识库：接收方追问"这条判断出处"时，成品里只有原子 id 没有原子库就答不上；增量时也不必回生产工程。
- 不自动安装：安装是接收方的动作；生产方装进自己的宿主会污染宿主的技能发现。

实测参照（上一版记录）：上一版把"成品正文出现本机路径"定为不合格项，并把"打包门面"列为最容易漏掉的一步。

README 由 `assets/product-readme.md` 填槽生成；市场文件由 `assets/marketplace.json` 填 plugins 生成。这里不重复。

## 常见失误

- 手改成品里的 SKILL.md：下次 deliver 会被草稿覆盖。改草稿，重新 deliver。
- 成品 README 复述流水线：接收方不关心怎么产出来的，关心怎么用、边界在哪。
- 只在成品根放 fact_check.py：接收方按 README 只拷 `skills/` 下的目录进宿主，根目录的脚本不会跟过去；每个技能要自带。
- 用 ZIP 交付却不留展开目录：接收方装完发现问题，生产方找不到对应版本。展开目录是主交付形态。
