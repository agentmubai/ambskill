# 07 S7 验收：出题、答题、盲评、判定

## 目标与产出

证明新成品比"没有它"强在哪、强多少、弱在哪一层。裸模型必是对照；有旧版成品就加进来；两位评委盲评五维；按明确门槛判 PASS / WEAK / FAIL。

产出：`work/tests/<题集>/{questions.md, answers/<来源>/<任务>.md, packets/, key.json, scores/<任务>-J1.md, scores.json, report.md}`、`work/docs/验收报告.md`。默认完成 = 至少一套题集全部 PASS，验收报告在。带 WEAK 交付须 `--force`，验收报告写明弱项；成品 README 同步写明，不写工程路径。

## 动作

0. `beiming.py lint` 全部技能通过才进盲评：体检过不了的不测；体检过了不等于好。
1. `beiming.py evaluate questions --testset 常备` → 派一个子代理出题（出题者不读技能，题里无方法名）。
2. `beiming.py evaluate answers --testset 常备 --sources bare,new[,old]` → 每个 (来源 × 任务) 一份提示词，各派一个子代理。**同一轮所有来源用同一个答题模型**。旧版成品用 `--old <其 skills 目录>`。
3. `beiming.py evaluate judge --testset 常备` → 打乱成甲乙丙丁，生成两位评委的提示词，各派一个子代理。评委只读盲评包与知识包模块摘要。
4. `beiming.py evaluate tally --testset 常备` → 按 任务 × 题 × 来源 × 两评委 的完整矩阵解析评分行（路由器题在内）；缺一格、重复、五维超量程、总分 ≠ 五维之和、judge 时被跳过的任务，都逐格列出并退出码 1，S7 不算完成；均分不掩盖缺格。补齐后重跑。
5. `beiming.py evaluate report --testset 常备` → 先查 tally 记录通过且未过期，再出 report.md：每任务 PASS / WEAK / FAIL 与主因、扣分回哪一层。矩阵不完整时它拒绝出判定。
6. WEAK / FAIL 的任务：扣分层是道/术 → 知识包里没有，回 S5；法/器 → 有但技能没调用或没写核对，回 S6。改完只重答 new（其余答卷复用），重新 judge → tally → report。
7. 修订两轮以上后必须换题集：`--testset 泛化`，再 `--testset 暴力`。掉回 WEAK 就是过拟合，回去改法而不是改题。
8. 写 `work/docs/验收报告.md`（模板见下），把 report.md 的结论翻译成使用者能读的话。

## 规则

- 五维定义与打分锚点在 `assets/prompts/evaluate-judge.md`；维度 → 层：方法选择→法·分支，成品可用→法·交付，原法忠实→道/术，材料贴合→器·事实，自检返工→器·核对。
- 判定门槛（eval_report 实现）：FAIL = 差距 ≤ −1 或 原法忠实 ≤ 2 或 反转题方法选择 ≤ 1 或 材料贴合 ≤ 2；WEAK = 非 FAIL 且（|差距| < 1 或 原法忠实 < 3.5 或 反转/近邻题方法选择 < 3 或 成品可用 < 3）；PASS = 其余。路由器：每题方法选择 ≥ 4 PASS，有一题 < 3 FAIL，其余 WEAK。
- 三套题集：常备（正常 / 反转 / 近邻 + 路由器 明确 / 复合 / 追问）→ 泛化（带材料 / 错误前提 + 路由器 复合 / 模糊 / 越界）→ 暴力（对抗题）。题集越靠后越像真实使用。
- 路由三题判定：明确请求归对；复合请求拆分顺序对且说明前一个产出怎么喂后一个；任务后追问导航到对的下一个。三题都对才算路由 PASS。
- 评委约有 1 分波动：差距 < 1 不解读；评委打的是同一盲评包内的相对分，不拿对照的绝对分说它退步。
- 两版成品对比时，任务列表可能不同：只比两版都有的任务；新版独有的任务只与裸模型比；旧版独有的写进验收报告"未覆盖"。
- 生成与评审都是模型；验收报告必须写明"真正的效果要使用者用过才知道"。
- tally 只认格式合规的评分行（五维 ≤ 5、总分 ≤ 25、标签为甲乙丙丁），其余按解析问题报出来。

## 依据

外层：基线对照与盲法评审——分数本身不重要，与裸模型基线的差才是技能的增量；布鲁姆分类与迁移测试——反转题测迁移、近邻题测边界，只会复述方法名是记忆层。

内层（可观察）：
1. 同一题集内所有来源用同一个答题模型。
2. 评分矩阵完整：每个任务（含路由器）× 每题 × 每个来源 × 两位评委各恰好一行，五维 0–5、总分 = 五维之和、层值在六层枚举内。
3. 每个任务的 PASS / WEAK / FAIL 有数值依据。
4. PASS 与它的依赖绑定：题集、key、每份评分文件、scores.json、tasks.json 任一在 report 之后改动，该 PASS 记录变 stale，deliver 不再认，须重跑 tally → report。

为什么这样定：
- 反转题：只有一条路的技能在条件反转后给同样的答案，这是"知识没进分支"的直接证据。
- 差距 < 1 不解读：评委本身有噪声，小于噪声的差距不成立。
- 修订后换题集：定向修订是对着评语改的，分数一定涨，但可能只是学会了这套题。

实测参照（上一版记录）：三套题集里裸模型分别拿到 17.35 / 18.92 / 17.16（满分 25），装技能后 22.65 / 21.67 / 21.81——不比裸模型，会把 17–19 分的"底"当成成果；同一版技能换答题模型从 22.4 变 21.2，模型一换尺度就换；同一份未动的答卷重评从 21.2 到 20.0，评委约 1 分波动；泛化题集的分数（21.67）低于修订过的原题集（22.65）。

## 模板

`work/docs/验收报告.md`（对使用者写）：

```
# 验收报告：<工具箱名>

## 一句话
新版在 N 个任务里 X 个 PASS、Y 个 WEAK；比不用它平均高 D 分（满分 25）。

## 每个任务
| 任务 | 不用它 | 用它 | 差距 | 判定 | 强在哪 | 弱在哪（哪一层） |

## 你确认过的事
- 预检结论（日期）：…
- 加工样品（日期）：你说 …
- 能力方案（日期）：你确认了 … 个任务，改了 …

## 题从哪来
常备 / 泛化 / 暴力 各多少题，出题人不读技能；答题都用同一模型；两位评委盲评。
声明：评委看不到哪份回答来自哪个来源，但装了技能的回答带核对小节、槽位句、作者方法名，形式上可辨；生成与评审都是模型，分数是同一盲评包内的相对分。

## 没做到的
- 旧版有而新版没有的任务（两版对比时先写这一条：两版由不同执行者按各自数据定任务，交集可能很小，未覆盖的任务不进对比表）：…
- 语料不支撑的任务：…
- WEAK 的原因与我们打算怎么补：…

## 提醒
生成与评审都是模型完成；真正的效果要你用过才知道。用得不顺的记下来，是下一轮增量的输入。
```

## 常见失误

- 出题人读了技能：题里带着方法名，新版必然高分。
- 一位评委：单评委的偏好无法校正；两位不一致的题要看理由。
- 评委读了 answers/ 或 key.json：盲评失效，整轮作废。
- 修了技能后重答所有来源：浪费且引入模型漂移；只重答 new。
- 只报总分：使用者要知道"哪个任务能用、哪个还不能"，分维度与分层才有行动意义。
